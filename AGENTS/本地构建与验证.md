# 本地构建与验证

适用于 Core。平台范围见 [全平台系统支持的最低版本](全平台系统支持的最低版本.md)，发布许可见 [发布与分发规范](发布与分发规范.md)，报告要求见 [测试文件与报告的管理](测试文件与报告的管理.md)。以下命令是使用说明，不是已执行证据。

## 本地质量检查与自动化边界

当前手动运行本地检查，不启用 GitHub Actions，不假定已有自动 pre-push 或服务器强制门禁。实际 Cargo 发现、归属、执行、失败保全和同名报告由 `Tools/test_reports.py` 管理；格式、Clippy、独立业务语义及真实 ABI／平台验收分别记录。

```sh
cargo fmt --all --check
cargo clippy --locked --offline --all-targets -- -D warnings
python3 Tools/test_reports.py --check-layout
python3 Tools/test_reports.py --run --evidence-dir /private/tmp/nodus-validation-evidence
cargo run --locked --offline --example error_contract -- --check
python3 Tools/test_reports.py --check-reports
```

每条命令检查真实退出状态；部分执行、编译失败、忽略、未测及旧指纹不能冒充通过。证据记录源码提交、dirty、命令、环境和原始日志；不以报告生成成功覆盖失败。单个 Rust 套件可用 `--run --suite <已登记套件>`；Python 工具使用登记的 `--external` 入口。

## 本地 macOS 成品

```sh
python3 Tools/build-apple.py --list
bash build-macos.sh --output <全新目录>/NodusCore.xcframework --package-dir <全新附件目录>
```

`--list` 只查看支持矩阵，不构建。当前默认仅 macOS arm64；不得自动构建其他平台。输出目录必须不存在；SDK、Rust target 与最低部署目标显式固定，头文件、模块、架构、ABI、Mach-O 平台、最低系统及来源 SHA-256 与实际产物一致。可复用的中间构建缓存位于忽略目录 `target/apple`；临时任务产物完成后清理，不删除他人未提交工作。

成品默认仅本地保存，不创建远程 Release／草稿／标签，不上传二进制或配套文件。构建成功不证明最低系统运行、真实权限、系统 VPN 或外部协议验收。
