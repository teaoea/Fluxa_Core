# 发布与分发规范（MUST）

作者：可莉唯一的狗。2026-10-23 用户修订。

## 仓库与开源边界

- Nodus 内核源码仓库为 `https://github.com/teaoea/Nodus-Core`，已开源；自有代码采用 MIT，保留第三方许可证及来源。
- 内核源码、C ABI、测试、构建脚本和文档统一维护于该仓库。后续二进制也从此仓库分发，不再要求源码与成品分仓。
- 内核开源不授予其他项目源码、用户数据或凭据的使用及同步权限；不得夹带与内核无关的内容。
- 永久禁止 crates.io，Cargo 保持 `publish = false`。

## 本地交付与授权

- 默认只在本地构建和验证；遵循系统支持列表、当前构建列表及 `nodus-core-{os}-{arch}[-{abi}]` 命名。
- 本地产物记录版本、源码提交、dirty 状态、架构、ABI、最低系统、实际验证及 SHA-256；不得把编译通过当作最低系统、真机或系统 VPN 验收。
- 源码提交和推送不构成上传授权。不得覆盖既有版本、移动历史标签或删除历史远程内容。
- 每个二进制交付包必须同时包含对应版本的对外 API 文档、错误代码查询表 Markdown 与机器可读 JSON；不得用独立文档附件代替同包要求。API 文档放在包内 `Documentation/API/External/`，排除内部自用 API；源码／示例引用固定到实际来源提交，包内相互链接有效。生成包及 SHA-256 清单时核对文档版本、错误 JSON 与二进制来源一致。
- 成品仅包含需要的二进制、公开头文件、上述对外 API／错误契约、许可证及有限来源清单；不得包含凭据、CA 私钥、用户配置、流量或内部日志。
- 发布前固定来源并完成适用的格式、Clippy、Rust、C ABI、真实宿主及平台验证；失败、跳过和未测边界必须真实记录。下载核对校验值后才可公开，稳定版本须另有明确授权。
