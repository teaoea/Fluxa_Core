# 发布与分发规范（MUST）

作者：可莉唯一的狗。生效日期：2026-10-19。

本规范落实用户最新发布要求，替代所有旧文档中允许发布 crates.io、在源码仓库发布二进制或向公开仓库同步源码的条款。API 兼容性、SemVer、测试、隐私、签名及 main 合并授权要求继续有效。

| 仓库 | 职责 | 禁止内容 |
| --- | --- | --- |
| 私有 `teaoea/Fluxa_Core` | Rust 内核源码、C ABI 定义、构建工作流、测试及开发记录 | 二进制 Release 附件、原生包 Git 文件、crates.io 发布 |
| 私有 `teaoea/Fluxa` | App、Swift 封装、平台适配、工作流、测试及开发记录 | App 二进制 Release 附件、安装包 Git 文件 |
| 公开 `teaoea/libfluxa-core` | 内核编译产物的 Release 附件、SHA-256、有限来源清单及发行说明 | Rust/Swift 实现源码、测试源码、构建脚本、完整源码压缩包、凭据 |
| 公开 `teaoea/fluxa-app` | App 预览版、测试版、稳定版的 Release 附件、SHA-256、有限来源清单及发行说明 | App/内核实现源码、测试源码、构建脚本、完整源码压缩包、用户数据 |

## 强制边界

1. 永久禁止任何分支、本机、CI 或正式流程向 crates.io 发布；不得配置或使用其发布凭据。Cargo 使用 `publish = false`，不得以 main 正式来源为例外。
2. 构建与测试只在私有源码仓库及受控本机环境运行。公开仓库不保存工作流、源码或 Git 历史镜像；不得复制私有仓库的 `.git`、提交树或源码标签对象。
3. 二进制只通过对应公开仓库的 Release 附件分发，不作为 Git 普通文件提交。必要许可证及公开 C ABI 声明随编译框架交付，不包含实现源码。
4. 公开仓库的标签指向本仓库的有限来源清单提交；清单另行记录真实私有源码提交，不能把不同仓库的提交号伪装成同一个 Git 对象。
5. GitHub 自动生成的 `Source code (zip/tar.gz)` 仅包含分发仓库本身的清单。不得为使标签可用而把私有源码推到公开仓库。
6. 只上传固定白名单成品，检查路径、展开尺寸、实现源码和构建脚本。严禁上传节点凭据、CA 私钥、用户配置、流量或任意日志目录。
7. 必须固定源码、版本、架构、构建号、验证记录与 SHA-256。先草稿上传，重新下载校验后才公开；已有版本不可覆盖，标签不得移动，失败不能回退至源码仓库。
8. 跨仓库令牌仅授权两个分发仓库的 Contents 读写，使用有限有效期保存在本机安全凭据存储或短期进程环境中，不依赖 Actions secrets，不写入源码、聊天或公开清单。默认 GITHUB_TOKEN 不具备跨仓库发布权限。

## 渠道与验收

- 内核 dev：每个通过门禁的提交发布独立不稳定版本，标签包含内核版本和完整源码提交；Pre-release，禁止更新稳定 latest。
- App 预览版：用于开发预览，Pre-release；App 测试版：用于功能验收，Pre-release。二者明确说明签名和未测边界，不能伪装成稳定版。
- 稳定版：只接受已获相应合并/发布授权的 main 源码及完整验证；macOS App 还须验证适用签名、公证与分发条件。不能仅改渠道名称绕过门禁。未完成稳定发布入口时保持关闭，不能沿用已删除的旧流程。
- 运行测试、成功上传、生成版本标签都不能代替 main 合并授权或真实系统 VPN 验收。

## 本机手动发布（2026-10-19 用户修订）

- 内核发布不使用 GitHub Actions。工作流仅保留可选手动测试，禁止由 push 自动发布。
- 本机从确定的 dev 提交执行格式、Clippy、Rust 测试、错误契约和真实 Swift FFI；记录失败与未测范围。检查摘要绑定提交、完整源码指纹和退出码；公开清单只保存该摘要 SHA-256，不公开内部路径、日志或源码。
- 从干净提交构建，使用 Tools/dev-release.sh --prepare 生成三个白名单附件；无需发布令牌即可准备。将附件手动上传到 libfluxa-core 草稿；重新下载并核对 SHA-256、来源清单和包内容后，标记 Pre-release 并公开，禁止更新稳定 latest。
- Tools/publish-core-binaries.py 是可选的本机上传助手；只能使用明确提供的现成分发授权，不要求配置 Actions secrets。缺少认证时可使用已登录的 GitHub 网页完成同样流程，不创建或扩大凭据权限。

## 七步交付流程

1. 私有内核 dev 开发，Rust API/C ABI 保留在内核仓库，Swift 封装保留在私有 Fluxa 仓库。
2. 内核 Rust、真实 Swift FFI、实际协议与目标平台验证，记录失败和未测范围。
3. 只提交本次文件，中文提交并推送私有内核 dev，确定源码提交。
4. 从确定源码构建并校验，只向 `libfluxa-core` 发布原生编译附件及来源清单；不发布 crate 或公开 Swift 源码包。
5. Fluxa 固定引用 `libfluxa-core` 的具体版本 URL 和 SHA-256，验证下载，无本地 Rust 构建或目录回退。
6. 在私有 Fluxa 仓库完成 API/平台接入，保持已确认 UI 布局。
7. 完成 App 回归、构建、打包和对应运行检查，中文提交推送私有 dev；按验收状态向 `fluxa-app` 发布相应渠道，记录 App 源码、内核来源及包校验值。

旧发布附件为历史记录，不等于授权今后继续使用旧路径；删除历史 Release、迁移历史标签和撤回旧 crate 需另行明确处理，不在本次修改中擅自执行。
