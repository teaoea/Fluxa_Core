# 全平台系统支持的最低版本（MUST）

## 系统支持列表（开发必须兼容）

| 平台               | 最低系统版本              | 架构范围                                |
| ------------------ | ------------------------- | --------------------------------------- |
| macOS              | 13.0                      | 仅 Apple Silicon / arm64                |
| iOS                | 16.0                      | arm64 真机与 Apple Silicon arm64 模拟器 |
| iPadOS             | 16.0                      | 复用 iOS arm64 真机与模拟器切片         |
| tvOS               | 17.0                      | arm64 真机与 Apple Silicon arm64 模拟器 |
| Android（仅 Core） | 8.0 / API 26              | arm64 / arm64-v8a                       |
| Windows（仅 Core） | Windows 10                | arm64、x86_64                           |
| Linux（仅 Core）   | Kernel 5.10 且 glibc 2.28 | arm64、x86_64；GNU/glibc ABI            |

- 不支持 Intel Mac / x86 Mac；不生成 Intel macOS 或 x86 Apple 模拟器切片，不以 Rosetta 作为支持或验收路径。Windows/Linux 的 x86_64 不受此限制；不自动扩展到 32 位 x86 或 ARM。
- 不支持 Mac Catalyst、watchOS、visionOS；不生成对应切片、构建目标或分发包。
- Linux 两项最低条件必须同时满足；不能用较新 Kernel 掩盖 glibc 不兼容。musl 是另一 ABI，当前不在支持范围；不得将 musl 产物标成 GNU。

## 构建列表（当前执行范围）

系统支持列表决定代码、依赖、条件编译和接口设计必须兼容的范围；构建列表决定本阶段实际编译、打包和交付的目标。两者不得混同。暂不构建不等于取消系统支持；列入系统支持也不代表已经构建、真机或最低系统验收通过。

| 当前状态 | 平台与架构                            | 构建及交付约束                                                                |
| -------- | ------------------------------------- | ----------------------------------------------------------------------------- |
| 启用     | macOS 13.0+／arm64                    | 当前日常仅构建此目标，按强制命名保存在本地。                                  |
| 暂不构建 | iOS／iPadOS arm64 真机及 arm64 模拟器 | 等用户明确要求该平台构建时再启用；开发时保持 iOS／iPadOS 16.0 兼容。          |
| 暂不构建 | tvOS arm64 真机及 arm64 模拟器        | 等用户明确要求该平台构建时再启用；开发时保持 tvOS 17.0 兼容。                 |
| 暂不构建 | Android arm64                         | 等用户明确要求该平台构建时再启用；开发时保持 Android 8.0／API 26 兼容。       |
| 暂不构建 | Windows arm64、x86_64                 | 等用户明确要求该平台构建时再启用；开发时保持 Windows 10 兼容。                |
| 暂不构建 | Linux arm64、x86_64／GNU              | 等用户明确要求该平台构建时再启用；开发时保持 Kernel 5.10 且 glibc 2.28 兼容。 |

- Core 默认构建命令只选择 macOS arm64；不得因平台工具链已安装、检查支持矩阵、完成开发或执行交付流程而自动构建其他平台。
- 保留其他支持平台的 target、最低版本、条件编译边界和强制产物命名。日常开发检查平台专有 API、依赖、路径、线程、文件权限与 C ABI 的可移植性；不得将实现写死为 macOS，也不能将其他平台的核心功能无条件替换为 Unsupported 来冒充兼容。
- 当前实际编译、静态契约检查、最低系统运行与真机验收分别记录。未实际构建的平台写明“未构建／未验证”，不能用 macOS 测试或模拟数据宣称其他平台通过。
- 启用其他平台构建须有用户明确指示，再显式选择目标并分别验证；既有其他平台本地历史产物不代表后续自动构建或上传已获授权。
- 构建列表不构成安装、上传或发布授权。

## 最低版本实施与验收（MUST）

1. 新功能、依赖升级、Apple 平台接口与 Rust/C/C++ 系统调用必须满足上述版本。高版本 API 有明确 availability 检查及有效回退；不可用能力明确拒绝，不放宽权限、生命周期、预算及错误契约，不自动回退直连。
2. Apple 构建显式固定 Rust target、SDK、部署变量、framework 元数据与 Mach-O 平台和最低版本，禁止继承主机/SDK 默认值。iOS/tvOS 的真机与模拟器须分别构建，不得相互替用。
3. Android 固定 NDK 及 API 26 的目标编译器/链接器，并核验依赖符号；Windows 固定对应架构的 MSVC 工具链/SDK，以 Windows 10 API 为边界；Linux 使用 glibc 2.28 或更低基线的受控 sysroot，并核验所有动态依赖和 GLIBC 符号版本不高于 2.28。
4. 静态库也必须核验最终宿主链接的系统依赖和最低系统；仅修改版本字段或在较新系统编译成功，不证明可以在最低系统运行。不得宣称未经核验的依赖已经兼容。
5. 最低系统编译、最低系统实际运行、最新系统运行、真机、模拟器、签名、平台接口和系统 VPN 分别记录。支持表是强制目标，不是已交付或已验收证明；缺 SDK、交叉工具链或运行设备时明确未验证，禁止造假或静默删除平台。
6. Core 产物的架构、包内平台、头文件、模块与符号必须一致；来源和校验清单必须对应实际二进制，不能混用不同构建。

## Core 发行产物命名（MUST）

- 发行产物基础名唯一采用 `nodus-core-{os}-{arch}[-{abi}]`，扩展名追加在基础名之后。禁止使用 macOS-xf、通用无架构包名或不包含系统的名称替代。
- `os` 固定使用小写 `macos`、`ios`、`tvos`、`android`、`windows`、`linux`；iPadOS 共用 ios 产物，不重复发布相同二进制。
- `arch` 使用 `arm64` 或 `x86_64`；禁止笼统写 arm、x86 或误将 32 位架构映射为 64 位。
- `abi`：Apple 真机及 macOS 省略；Apple 模拟器使用 `simulator`；Android 省略（arm64 对应 NDK arm64-v8a，最低 API 另记清单）；Windows 使用 `msvc`；Linux 使用 `gnu`。新增 ABI 必须明确约定，不能擅自加入 musl/GNU 混用或覆盖既有产物。
- 支持范围对应的 Apple 包名（仅构建列表启用的目标实际生成）：`nodus-core-macos-arm64.zip`、`nodus-core-ios-arm64.zip`、`nodus-core-ios-arm64-simulator.zip`、`nodus-core-tvos-arm64.zip`、`nodus-core-tvos-arm64-simulator.zip`。每包仅含对应平台/架构/ABI 的切片，禁止包名与实际切片不符。
- 其他系统的命名示例：`nodus-core-android-arm64.zip`、`nodus-core-windows-x86_64-msvc.zip`、`nodus-core-windows-arm64-msvc.zip`、`nodus-core-linux-x86_64-gnu.tar.gz`、`nodus-core-linux-arm64-gnu.tar.gz`；示例不是产物已经构建的证明。
- 内部库名始终为 `nodus_core`；系统惯用前后缀属于格式的一部分，例如 `libnodus_core.a`、`libnodus_core.so`、`nodus_core.lib`、`nodus_core.dll`。Apple framework 使用 `nodus_core.framework/nodus_core`，Clang 模块名为 `nodus_core`；XCFramework 容器可保留 `NodusCore.xcframework`，公开 C ABI 函数不因包名改变。
- 同名产物按版本/源码提交目录隔离，不覆盖旧文件。随本地交付保存版本、完整源码提交、dirty 状态、架构、ABI、最低系统、构建工具链、实际验证与未测边界及 SHA-256 清单。

## 分支与上传授权（MUST）

- Core 统一使用 main 开发，不保留 dev 分支。开发中的版本仍可使用预发布后缀；分支名、版本稳定性与二进制发布授权互不替代。已正式发布的契约仍受兼容性与变更授权约束。
- Core 二进制及配套发布文件默认只在本地编译、校验并保存。源码提交和推送不构成二进制上传、远程 Release 草稿、标签或公开发布授权。未经用户明确许可禁止上传；永久禁止 crates.io。

独立测试服务属于辅助工具，不作为 Core 库包；采用 nodus-core-fixture-{os}-{arch} 标识，不能冒充上述内核发行产物。
