# 配置与资源文件所有权（MUST）

作者：可莉唯一的狗。生效日期：2026-10-21。适用范围：Core、App、Network Extension 及其他宿主。

## Core 是配置的只读消费者，不是配置管理者（强制约束）

Core 仅负责读取、解析、校验和执行外部提供的配置。任何配置文件的创建、修改、覆盖、删除、持久化及目录管理行为，均由主 App、CLI 或平台适配层承担。

Core 不得自行修复、重写或保存配置。配置异常时，应返回明确错误，不得擅自修改原始文件。Core 对外部配置和资源只读，禁止修改；该约束同样适用于 Network Extension。

## 文件与目录归 App／宿主所有

- 配置、插件、JS、规则、GeoIP 及其缓存的目录选择、权限获取、创建、列举、保存、重命名、删除、迁移、下载落盘及原子替换均由 App／宿主负责。Core 不推断 App Group、HOME 或默认目录，不创建目录、锁文件、索引、配置、日志或缓存，不启动落盘更新任务。
- Core 接收宿主明确提供的配置文件绝对路径及必要的只读资源引用，负责有界只读加载、严格解析、语义校验、规则编译、JS 运行及实际网络处理。未知或无权限路径明确失败，不搜索其他目录或回退旧配置文件。
- 路径不是授权。Apple 宿主负责 sandbox、App Group、security-scoped URL 的获取和生命周期。扩展使用自身有权读取的共享文件；不能仅凭 App 的私有路径获得跨进程权限。
- 主配置、插件或远程规则正文不能自行扩展宿主文件访问范围；资源路径来自宿主明确授权的引用。读取大小、文件类型、链接、变更与生命周期由 Core 在读取边界验证，不将目录管理责任取回 Core。
- 内存配置、编译快照、DNS／连接／JS 运行时及缓存线程的业务生命周期、取消与资源预算仍属于 Core。磁盘资产管理权不等于将网络决策或活动资源控制权交给 App。
- 网络资源更新由 App／宿主发起并保存；可调用 Core 受控的网络能力取得有界响应，禁止在 Swift 重建代理、DNS、TLS 或业务网络管线。Core 不因资源不存在而自行下载落盘。
- 默认配置模板可以由 Core 以纯内容形式提供；是否新建文件、保存位置及覆盖决定由 App 作出。Core 不再直接初始化配置目录或保存配置。

## Network Extension 只读约束

- 扩展只读取宿主准备完成的配置和资源，不下载落盘、不保存、不创建目录、不修改、不删除、不迁移。
- Apple 不提供“只读 App Group” entitlement。共享容器 entitlement 仅赋予可访问性，不能声称它是 OS 级只读隔离；只读边界必须由扩展的接口与实际 Core 文件读取实现保证。
- 使用最小必要的共享容器权限；App 和扩展各自具有有效签名及相同平台的约定组标识，不使用普通目录冒充共享容器。
- 原子文件替换后的新配置由显式提交生效；Core 保留运行所需只读快照，旧引用不恢复已撤销的活动权限。权限、读取或解析失败保留现有有效运行配置，不伪造成功。

本规范替代旧的“Core 负责共享目录、默认配置创建、插件／规则／JS 下载落盘与持久缓存管理”职责描述。规范接入不代表旧实现已完成迁移，代码与测试必须另行验证并明确迁移状态。
