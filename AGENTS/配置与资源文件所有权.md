# 配置与资源文件所有权（MUST）

作者：可莉唯一的狗。生效日期：2026-10-21。适用范围：Core 的配置和资源只读访问。

## Core 是配置的只读消费者，不是配置管理者（强制约束）

Core 仅负责读取、解析、校验和执行外部提供的配置。任何配置文件的创建、修改、覆盖、删除、持久化及目录管理行为，均不属于 Core；Core 只消费宿主准备的输入。

Core 不得自行修复、重写或保存配置。配置异常时，应返回明确错误，不得擅自修改原始文件。Core 对外部配置和资源只读，禁止修改。

## Core 的文件与目录职责边界

- 配置、插件、JS、规则、GeoIP 及其缓存的目录选择、权限获取、创建、列举、保存、重命名、删除、迁移、下载落盘及原子替换均由宿主负责。Core 不推断 共享容器、环境变量或默认目录，不创建目录、锁文件、索引、配置、日志或缓存，不启动落盘更新任务。
- Core 接收宿主明确提供的配置文件绝对路径及必要的只读资源引用，负责有界只读加载、严格解析、语义校验、规则编译、JS 运行及实际网络处理。未知或无权限路径明确失败，不搜索其他目录或回退旧配置文件。
- 路径不是授权。Core 只能读取当前进程已获真实系统权限且经宿主明确授权的文件；任何路径或资源引用本身都不授予权限，Core 不负责取得或扩大系统权限。
- 主配置、插件或远程规则正文不能自行扩展宿主文件访问范围；资源路径来自宿主明确授权的引用。读取大小、文件类型、链接、变更与生命周期由 Core 在读取边界验证，不将目录管理责任取回 Core。
- 内存配置、编译快照、DNS／连接／JS 运行时及缓存线程的业务生命周期、取消与资源预算仍属于 Core。磁盘资产管理权不等于将网络决策或活动资源控制权交给外部调用方。
- 网络资源更新由宿主发起并保存；Core 对外仅提供受控网络能力及有界响应。Core 不因资源不存在而自行下载落盘。
- 默认配置模板可以由 Core 以纯内容形式提供；是否新建文件、保存位置及覆盖决定由宿主作出。Core 不再直接初始化配置目录或保存配置。

原子替换后的配置必须经显式校验和提交才生效；Core 保留运行所需的只读快照，旧引用不得恢复已撤销的活动权限。权限、读取或解析失败保留现有有效运行配置，不伪造成功。
