# udp.rs 代码说明

## 职责（干嘛的）

对应源码：`src/tun/udp.rs`。本页说明实现职责、数据流程和边界；公开调用的请求／响应契约单独维护于 `Documentation/`，开发约束维护于 `AGENTS/`。

## 目标（想达成什么）

把 TUN UDP 包接入受控 DNS／Fake-IP 和共用出站，正确编码关联响应而不发送合成 IP 到真实网络。

## 主要流程与模块协作

Session 检查 UDP/IP、DNS 端点及传输保护；本地 DNS 交给 Resolver，普通目标按所属代次恢复域名并执行出站；返回包交换端点，队列、任务及取消受会话预算约束。

## 输入、输出与失败边界

输入来自受约束的配置、明确授权的资源或校验后的网络数据；各入口的实际类型、字段和值域以下文及对应源码为准。正常结果只能说明该模块完成其职责，不能推定网络接管、其他模块初始化或外部权限已经成功。非法输入、协议错误、系统故障、取消和资源不足沿用 `src/error.rs` 的真实分类；不静默改为 DIRECT，也不修复或覆盖外部配置。

活动资源由 Core 的会话身份、有效租约、取消及明确关闭操作管理；只读快照引用不构成活动权限。内存与任务的实际存活期计入对应预算。具体模块没有活动任务时，不因本说明增加后台线程或额外权限。

## 实现细节

## 数据路径

完整 IPv4/IPv6 UDP/IP 包进入 `tun::udp::Session`。目标是显式 `dns_endpoints` 时，复用 `Resolver::respond`、上游缓存、DoH/DoT、DNSSEC、排除列表及标准 DNS 错误响应，生成交换源/目标的返回包。DNS 失败回应 SERVFAIL，不回退直连，不将失败解释为未命中。畸形请求回应 FORMERR；过大 UDP 响应按现有 EDNS 512–1232 字节预算返回 TC，保留 TCP 重试所需语义。

目标是本会话解析器合成池内的地址时，自动取所属解析器代次。共用出站恢复域名、真实解析候选地址，再执行既有域名优先规则及连接流程；不发送合成地址。域名命中动作后跳过 IP 规则的产品约定保持不变。没有域名命中时仍检查真实候选 IP 的保守拦截。返回包使用原合成地址作为源地址。

DNS 查询本身是本地解析服务，不把被查询域名作为 DNS 传输的目的地路由；它沿配置的 DNS 上游解析。查询得到的合成目标在连接阶段执行目标规则。全域 UDP 拦截仍拒绝虚拟 DNS UDP 请求。

## 接口与限制

当前 C ABI 为版本 2，使用现有二进制 submit/receive 及关闭入口；能力位 24。`tun_udp_open` 的可选 `dns_endpoints` 是最多两个数字 IP 端口（必须 53），默认空列表，未知字段拒绝。Swift 的 `NativeTunUDPClient` 对应 `dnsEndpoints`，仅传递值，不处理报文、映射或路由。

端点不得落入所配置的 Fake-IP 池，避免分配撞址。例如合成池 `198.18.0.0/16`、`fd00:198:18::/64` 时使用 `198.19.0.53:53`、`[fd00:198:19::53]:53`。主配置仍使用原 `dns` 字段；会话参数不新增主配置启用开关。完整中英文 YAML 注释包含调用示例。

会话创建时保留解析器 Arc。新 DNS/Fake-IP 请求只接受该解析器仍属于当前快照；替换解析器后明确拒绝，宿主需关闭并重开会话，同一进程的 TUN 池共用分配高水位，退役地址不能在新会话重新解释为其他域名。普通 API 的历史分配也计入高水位；接管后的同范围普通查询共用安全游标，外来解析器地址仍不能用于本会话。最多同时登记 16 个有效池租约，内核按身份、Generation 和 Active/Closing/Closed 状态检查占用；Arc/Weak 不参与业务占用判断。关闭完成后回收占用，即使旧解析器、快照或会话对象仍被引用也允许新会话重绑；仍有效且范围不相同的重叠租约拒绝绑定。退役池不阻止配置区间变更：IPv4 用覆盖 198.18.0.0/15 的 16 KiB 固定位图记录已分配地址，IPv6 使用最多 4096 个可合并的已分配区间，首次登记前从既有 16 MiB 映射预算预留 256 KiB。历史记录不保存域名，且不随解析器释放；新 TUN 分配同时跳过任一地址族的已分配地址，碎片区间额度或地址耗尽返回资源错误。该额度限制实际地址历史的碎片数，不按历史配置数量计数。池地址耗尽明确报错，不回绕。已有普通 API 映射的解析器不能直接转换为 TUN 池，需创建新解析器。跨进程不持久化高水位，后续系统隧道生命周期必须隔离旧缓存/旧流，不能声称跨重启安全已验收。旧会话已有 UDP 流继续使用其已检查的真实对端；关闭时全部取消。规则更新而解析器所有者未变时，新流采用新路由快照，旧流保留原策略。映射清除后新流拒绝旧地址，同实例不复用已分配地址。

每会话一个提交在途，最多 8 会话；DNS 查询复用全局 16 查询预算，不逐包新建任务。先占用有界输出槽，再查询/分配；满队列立即返回配额错误。Fake-IP 每解析器最多 4096 条，映射全局预算 16 MiB、输出包全局 4 MiB；上述配额上限保持不变。Rust close 改为异步等待；撤销权限、停止所属连接/驱动/监听及等待任务退出后，立即归还会话和解析器活动额度。真实保留的配置、缓存和映射继续持有内存预算。新解析器元数据预算为 16 MiB，驱动任务最多 64 个/解析器并从全局 16 MiB 预算每项预留 128 KiB；该估算不等于整个进程 RSS 的硬保证。不停止共享 Manager，不保存宿主指针。

## 验证范围

专项 Rust 测试覆盖真实上游、IPv4/IPv6 DNS 包、合成查询不触及上游、Fake-IP 到实际 IPv6 UDP 对端再返回原合成地址、映射清除、解析器同池换代、FORMERR/NXDOMAIN/SERVFAIL、背压、配额、错误所有者代次、端点碰撞、UDP 拦截、取消、普通包与重开。

独立 Swift FFI 构造 IPv4 包，验证合成响应、无需宿主代次的真实 UDP 转发、配置替换拒绝、关闭及 40 次资源回收。App 必须另用已发布二进制复验；发布来源和最终结果在交付记录补充。

TCP DNS 入站、TCP TUN 流、分片、系统 Network Extension 尚未交付。大响应 TC 后的 TCP 请求明确 Unsupported，不能宣称所有 DNS 流量可用。没有实际系统 VPN、最低 macOS 14、Intel 或其他平台运行验收。本阶段不修改系统设置、不新增日志通道。

## v2.2.1 隔离修复

补齐普通 API 接管前、接管后与 TUN 所属解析器之间的地址池隔离。189 项 Rust 测试与 15 组真实 Swift FFI 通过，包括历史普通映射退役、普通新查询继续可用、外来映射拒绝。协议回归首次 Firefox 组遇到 30 秒超时，同条件复核 37 组全部通过；首次失败记录保留，未确认为稳定功能缺陷。

## 禁止行为（不允许做什么）

不得发送 Fake-IP 到真实网络、把 DNS 执行失败解释成规则未命中并直连，或在会话关闭后继续受理新包／恢复旧任务权限。

违反输入、授权或资源边界时，使用实际模块的既有错误／拒绝路径，不伪造成功或擅自扩大权限；具体失败后果以上文流程和公开契约为准。
