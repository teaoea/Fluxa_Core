# check.rs 代码说明

## 职责（干嘛的）

对应源码：`src/configuration/check.rs`。模块在不应用配置、不启动网络的前提下，把严格主配置错误转为有界字段路径和原文位置；目标是调用方能定位真实问题，同时保持与实际解析相同的语义。

## 目标（想达成什么）

在不改变原配置和活动状态的前提下提供与真实解析一致、可定位且不泄密的错误诊断。

## 输入与流程

check_yaml 接收未格式化的原始 UTF-8 文本，复用 Document 的严格解析和语义验证。定位扫描维护映射／序列的源标记，与错误发生的字段路径关联；不靠中文错误字符串猜测位置。check_file 复用 storage 的授权绝对文件只读入口，再检查读入正文。

## 结果与位置

成功返回 Summary；失败返回 Box<CheckIssue>，含既有 ErrorInfo、有界 field 和可选 SourcePosition。字段定位可能指向完整条目而非内部值，缺失可靠原文位置时返回 None。file 访问失败不伪造 YAML 行号。逻辑 line／Unicode 标量 column 从 1 开始，utf16_offset 从 0 开始；自动视觉换行不能由 Core 推断。

## 失败、资源与验证

沿用主配置输入长度、深度、字段、重复键和预算要求，返回首个问题。代码不写回或修复正文，不遍历下载插件资源，诊断成功不构成网络启动许可。原文换行、中文、表情和 CRLF 必须保持，异步调用方仅对同一版本正文使用偏移。

公开签名和例子见 [check_api.md](../../Documentation/API/configuration/check_api.md)；[test_configuration_check.rs](../../tests/test_configuration_check.rs) 及 [同名文档](../../tests/test_configuration_check.md) 保存实际字段、Unicode、只读和错误位置验证。位置算法正确不等于所有业务配置或外部资源均已验收。

## 禁止行为（不允许做什么）

不得通过格式化正文改变偏移、从错误文本猜字段、伪造第 1 行或视觉换行位置，不得在检查接口应用配置、遍历下载资源或启动网络。

违反输入、授权或资源边界时，使用实际模块的既有错误／拒绝路径，不伪造成功或擅自扩大权限；具体失败后果以上文流程和公开契约为准。
