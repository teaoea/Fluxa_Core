# VPN 四阶段事务驱动代码说明

## 职责（干嘛的）

2026-10-23。对应源码：`src/vpn/transaction.rs`。状态：事务驱动已实现，尚未交付系统 VPN。依据 `AGENTS/VPN启动技术规范.md`，现有 `vpn::Preparation` 仅提供候选资产准备，不能授予接管资格。

## 阶段与所有权

Core 保持唯一启动事务及其配置身份、资源预算、取消、阶段期限与实际结果。App 只提交启动/停止意图，协调可信本地确认、系统权限和 Network Extension。配置、订阅、普通 JSON 请求不能提交“检查通过”“已授权”或“已验证”的布尔值。

1. Preflight：严格配置和规则、必要出站与 DNS 实测、GeoIP、峰值预算、系统权限/能力、防回环和冲突检查；无节点需本次可信授权。
2. Prepare：固定同次配置与资源，登记回滚信息，准备受预算约束的运行时，再次核验检查/授权未过期。
3. Commit：按事务执行系统变更；每一已执行步骤均有所有者和条件化恢复动作。进入此阶段仍不能发布 Running。
4. Verify：检查真实 TUN 收发、路由/DNS 及必要出站路径；全部必要项成功且仍未取消，才可发布 Running。

## 失败和取消

开始下一阶段与取消请求共用同步边界。异步取消不能靠丢弃Future假定系统操作已停止；必须等待操作给出确定结果，再恢复已经发生的副作用。失败分别保存原故障和清理故障。清理失败保留实际未恢复项及可重试入口，不能宣称 Closed；重复/并发停止等待同一个清理结果。旧只读对象不保留活动租约。

恢复只撤销本事务仍拥有的变更，不覆盖其他主体后续设置。持久化上次 Running/授权不能恢复本次权限。进程/扩展失联恢复需要平台真实状态和所有权证据；纯状态机单元测试不能验收此项。

## 本次实现边界

实际四阶段驱动须先完成内核实现、错误协议、取消及逆序清理故障测试，然后扩展C ABI并接Swift。缺少真实平台或必要链路验证的情况下必须拒绝，不能用测试替身接通生产启动。具体代码、命令、结果及剩余缺口在实现后追加；此文不是实现完成或测试通过证明。

## 当前代码（未接生产）

`src/vpn/transaction.rs` 增加密封步骤接口及内核四阶段驱动；外部Rust、JSON、FFI不能提供Steps实现，也不能提交成功标志推进阶段。当前仅tests内有替身，没有生产Steps实现，因此尚无可启动系统VPN的入口，不增加C ABI能力位、不替换App内二进制。

内核全局仅保留一个接管事务，Running/清理中/回滚失败均拒绝新启动。取消和阶段准入共享锁；取消/超时等待原步骤确定结束才清理，步骤及清理panic通过JoinError报告，不脱离恢复。原失败和清理失败分别保存；清理失败保留全局对象和Unknown状态，即使Controller释放也可通过新控制入口按同一事务ID重试。成功停止后旧ID不能停止新启动。此处只实现驱动的调用顺序，具体系统变更的逆向所有权校验由后续真实平台实现完成。

尚未实现：真实必要链路/DNS/峰值预算检查、可信无节点授权、配置与系统证据有效期、平台系统操作及条件化逐步恢复、进程退出后的恢复、C ABI/Swift接线。阶段期限只对守约的内核步骤有效；若步骤不响应取消，保持未完成状态等待，不把超时冒称已清理。本次不声称完整四阶段事务已交付。

## 类型、输入与调用关系

`Controller`是只持有本次启动标识的控制入口；全局`ACTIVE`保留唯一事务的`Inner`，成功清理后仅保留状态摘要并释放步骤对象；回滚失败继续保留恢复对象，不依赖控制对象引用数裁决接管权。`Status`只包含内核分配的事务ID、阶段、系统状态及受限Error；无凭据、原始配置或系统设置。`current_status`支持入口重建后的恢复查询，`status(id)`拒绝不匹配ID，`stop(id)`请求取消并等待清理，`retry_cleanup(id)`仅允许重试回滚失败。

`begin`接收密封的内核Steps实现及大于0、不超过120秒的阶段期限；运行时就绪和独占准入成功后才登记事务，返回ID不代表接管。Steps目前只有同模块测试替身，外部crate无法实现私有Sealed，生产FFI没有注册入口。不能通过外部提交阶段名称、布尔值或JSON推进状态。

运行器按四阶段逐个准入，每个步骤在受监管任务内运行。超时发送取消、等待原任务结束，再进入清理；Verify成功后的Running准入仍受同一取消锁保护。步骤panic形成Internal原失败并清理；清理panic形成独立Internal清理失败并保留恢复入口。成功停止恢复后才允许下一次启动。全局记录最多一项，旧对象可保留只读摘要，但旧ID不能作用于替换后的事务；驱动及其工作资源由内核持有，具体峰值资源预算仍需真实Steps实现逐项计入。

## 错误与执行后果

期限输入错误返回InvalidInput；忙、旧ID及不允许恢复状态返回InvalidState；阶段超时在步骤确定结束后返回NetworkTimeout；取消形成Cancelled。阶段主动返回的错误原样保留，不转DIRECT。rollback失败单独记录cleanup_failure，system为Unknown；未真实完成清理不会报告Stopped。只读示例见`examples/vpn_transaction_status.rs`，隔离故障断言见`tests/test_vpn_transaction.rs`，历史候选回归见`tests/test_vpn.rs`。时间、版本、命令和实际结果仅记录在对应测试文档。

## 目标（想达成什么）

由 Core 统一串行推进四阶段、取消和确定性清理，分别保留原故障与回滚故障；缺少真实生产步骤时不提供系统启动能力。

## 禁止行为（不允许做什么）

不得通过外部可实现的 Steps 或 JSON 成功标志伪造检查／授权／验证，不得因丢弃 Future、超时或控制对象释放而宣称系统操作已停止；回滚失败不得覆盖为成功或允许新接管。

## 清理完成与步骤资源释放

`Inner.steps` 使用内部 `Mutex<Option<Arc<dyn Steps>>>`。每个阶段只在执行期间取得步骤引用；回滚返回成功后，在同一受监管任务中撤销存储的引用，在锁外完成析构，再发布终态并唤醒停止等待者。因此，保留 `Status` 或全局终态不再延长步骤对象及其内部资源的生命。外部自持的引用不由内核强制销毁，Steps 实现仍须在 rollback 中主动撤销活动资源权限。

回滚返回错误或 panic 时保留可恢复对象并阻止新启动。成功回滚后的步骤析构若 panic，驱动同样报告独立清理错误及 Unknown，不宣称资源释放完成；已析构的对象无法复活，缺失恢复对象时重试明确报 InvalidState，后续真实平台实现仍需独立恢复日志。该机制不是进程崩溃恢复或操作系统资源释放的证明。

## 真实网络检查入口

`begin_preflight`构造内部密封驱动，绑定同一全局事务槽和检查报告；`preflight_status`只读查询。网络条件通过后，缺少真实平台证据仍返回Unsupported，不进入Prepare。完整流程、资源限额和未实现边界见[preflight.md](preflight.md)。阶段期限触发取消时，步骤返回Cancelled或成功均由监督层记录NetworkTimeout，其他真实步骤故障不覆盖。
