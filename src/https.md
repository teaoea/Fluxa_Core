# https.rs 代码说明

## 职责（干嘛的）

对应源码：`src/https.rs`。本页说明实现职责、数据流程和边界；公开调用的请求／响应契约单独维护于 `Documentation/`，开发约束维护于 `AGENTS/`。

## 目标（想达成什么）

为普通 HTTP／HTTPS 请求提供统一、受限的连接和响应处理，维护目标身份及 TLS 信任。

## 主要流程与模块协作

HttpsClient 结合 network、http 与共用 outbound 处理目标规范化、路由／连接、TLS 与响应分帧；Response 保存受限响应，业务失败使用统一错误，不回退为未授权连接。

## 输入、输出与失败边界

输入来自受约束的配置、明确授权的资源或校验后的网络数据；各入口的实际类型、字段和值域以下文及对应源码为准。正常结果只能说明该模块完成其职责，不能推定网络接管、其他模块初始化或外部权限已经成功。非法输入、协议错误、系统故障、取消和资源不足沿用 `src/error.rs` 的真实分类；不静默改为 DIRECT，也不修复或覆盖外部配置。

活动资源由 Core 的会话身份、有效租约、取消及明确关闭操作管理；只读快照引用不构成活动权限。内存与任务的实际存活期计入对应预算。具体模块没有活动任务时，不因本说明增加后台线程或额外权限。

## 实现细节

本阶段实现主动 HTTPS 请求的 TLS 解密链路。Swift 客户端通过 C ABI 把请求交给 Rust，由 Rust 连接目标、验证服务端证书与域名、协商 TLS、发送 HTTP/1.1 并返回解密后的响应。浏览器 CONNECT 拦截属于第二项 MITM。

## 实现边界

支持 TLS 1.2/1.3，仅协商 HTTP/1.1；使用系统根证书，可由调用方明确指定额外根证书。额外信任只对当前引擎实例生效，配置接口目前保存单个额外根证书，重新调用会替换前一个；不安装系统证书、不忽略验证，也不跨客户端共享。无可用信任根时拒绝请求。

支持定长、chunked 和 TLS 正常关闭结束的响应。HEAD、204、304 没有响应正文；重定向保留原始状态与 Location，不自动跟随。请求主动要求 identity 编码，服务端仍返回内容编码时，正文为该编码的解密字节，本阶段不自动解压。

请求头最多 128 个、32 KiB，正文最多 8 MiB；一次完整请求最多 60 秒。FFI 同时最多执行 8 个命令，同一引擎拒绝并发重入。JSON 输入最多 12 MiB，输出最多 24 MiB（为第二项 MITM 的双正文捕获预留），待领取响应总量最多 32 MiB，实例与响应合计最多 64 个句柄。达到上限明确失败。超大、歧义或截断消息不会伪报成功。

拒绝 URL 内凭据、控制字符、非 HTTPS、请求头注入、重复或同时存在的 Content-Length/Transfer-Encoding、未知传输编码、WebSocket 升级和未支持的 trailers。调用方不能覆盖 Host、消息长度和连接控制头，Rust 统一生成。暂不支持 HTTP/2、HTTP/3、客户端证书认证、重试、自动重定向和流式返回；已实现能力不代表代理协议或网关可用。

## Swift 与 C ABI

`NativeHttpsClient` 负责资源生命周期、内部消息编码与解码。网络与证书判断全在 Rust。实例耗时调用应放在后台执行。`nodus_core_command` 同步调用，输入只在调用期间借用；结果返回 Rust 响应句柄，Swift 查询长度并复制到自己的 Data，随后调用统一 destroy。不可跨语言释放内存。

能力位 0 表示 HTTPS 客户端，能力位 1 表示 MITM。内部 JSON 是 FFI 的结构化传输，不是用户配置格式；用户主配置、规则及插件仍使用 YAML。响应正文采用 Base64 传输，Swift 返回 Data。Rust 错误不包含请求正文、URL 凭据或私钥。

## 共用服务连接管线（v1.3.0）

HTTP/HTTPS/MITM 已统一使用配置 DNS、实际路由和受管理连接；取消、空闲回收及资源所有权均沿用共用管线。未配置能力明确拒绝，TLS 信任与域名解密范围不改变。实现、发布来源及完整验证边界见 [Outbound.md](outbound.md)。

## 禁止行为（不允许做什么）

不得跳过上游证书与目标身份验证、跨主机复用不匹配的 Host、在代理失败时改为直连，或把截断／超限正文当作完整响应。

违反输入、授权或资源边界时，使用实际模块的既有错误／拒绝路径，不伪造成功或擅自扩大权限；具体失败后果以上文流程和公开契约为准。
