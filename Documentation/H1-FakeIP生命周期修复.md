# H1：Fake-IP 退役池生命周期修复

## 规范与实际缺陷

原始 TUN 包没有映射代次字段；旧地址不得重新分配给其他域名。配置变更不应因为已经释放的旧解析器永久阻止建立新会话；仍存活的重叠池保持拒绝，旧解析器所属代次校验保持不变。

旧 `src/dns/fake_ip.rs` 的 `TUN_POOLS` 保存强游标引用与永久 active 标记，历史条目从未删除；新区间与历史任一地址族重叠返回 `InvalidState`，16 个历史配置后返回 `ResourceLimit`。并非所有旧会话都永久失效：完全相同范围仍可以共享旧游标。

在提交 f3f633470378514be85e6f9782f1468b9a824eee 的独立源码副本加入相同 `Tests/fake_ip_lifecycle.rs`：释放旧 `/16` 解析器、Manager、Session，再创建 `/15`，实际失败为 `InvalidState`。日志 `/private/tmp/fluxa-h1-before.log`。修复后相同案例通过。

## 修改与安全不变量

- `Pools::namespace` 只登记最多 16 个同时存活的池，弱引用不延长绑定解析器生命周期。注册或分配时清除失效条目。同范围共享存活令牌，最后一个绑定解析器释放后才允许更改重叠范围。
- 会话 close 不等于释放所有外部 Rust Arc；宿主需要释放旧 Session、Manager 快照及解析器引用。C ABI 关闭/销毁仍按现有所有权释放，没有新增入口。
- 退役地址历史独立保留：IPv4 为 16 KiB 固定位图；IPv6 为排序、合并的最多 4096 个区间。首次使用从既有全局 16 MiB 映射预算预留 256 KiB，包含预留向量容量及保守余量；进程退出前保留该历史预算，不保存域名、配置正文或包内容。
- `Pools::allocate` 在同一互斥锁中查重并登记地址。绑定 TUN 的分配跳过任一地址族历史命中的地址，不能因为更改另一地址族绕过保护。IPv6 区间查找使用二分；扫描最多合法 IPv4 池大小，不回绕。
- `Pools::remember` 先检查区间数量、预算与向量容量，然后登记两个地址。失败不部分占用地址。相邻区间合并，额度约束实际历史碎片而非历史配置数；地址或区间耗尽明确拒绝。
- 普通非 TUN API 保留原有独立实例分配语义；历史分配仍登记供未来 TUN 接管保护，同范围存活 TUN 时普通查询也跳过历史。带已有普通映射的解析器仍不能直接转换为 TUN。
- `Table` 锁先于 `Pools` 锁，没有反向锁路径；历史注册表没有强业务对象引用。不使用 unsafe，不修改 DNS 前后决策、分流优先级、实际出站或 Debug 权限。

## 错误契约与兼容性

本次复用已登记的 9001 状态错误与 8001 资源错误；不增加、更名或复用公开代码。存活重叠池或已有普通映射绑定失败是状态错误；活跃池、地址历史碎片、预算或地址空间耗尽是资源错误。锁中毒保持已有内部错误。所有失败向 Session::new/FFI 传播，不转 DIRECT，不报告成功。

Rust API、C ABI v2、Swift 门面签名、配置字段及持久化格式不变。行为修复仅移除退役池造成的永久禁止；历史记录保留以满足旧地址隔离。回滚需将 crate、框架及远程包整体回退，旧版本可能重新出现 H1；本次不更新 App。

## 示例与测试证据

`cargo run --example fake_ip_reconfigure`：普通 Rust 程序不启动系统 VPN、不请求上游；旧 IPv6 地址 `fd00:198:ffff::1`，新地址 `::2`，旧地址反查无映射。

- `src/dns/fake_ip.rs` 六项独立语义用例：退役后扩大范围、任一地址族保护、40 次未分配池回收、共享令牌最后持有者、16 个存活额度与并发唯一分配、4096 个碎片准入失败原子性及合并回收。
- `Tests/fake_ip_lifecycle.rs`：独立进程真实 Resolver/Manager/Session 的 `/16` → `/15` 最小复现，旧地址无新映射。
- 原有 `Tests/tun_dns.rs` 八项 DNS/UDP/所属代次、旧地址、外来解析器、取消、配额与错误传播回归通过。
- `Tests/ffi_tun_dns.swift`：真实 Swift → C ABI → Rust，原有 40 次循环及新增 20 次重叠 IPv4、不同 IPv6 配置变更，实际 DNS 返回和 UDP 回环通过。
