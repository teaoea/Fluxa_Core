# 规则缓存写入安全修复与验收

作者：可莉唯一的狗。

## 缺陷与修复范围

H2：`Store::prepare` 排他创建临时文件后，旧 `cache::write` 又按路径执行 `write(true).truncate(true).open(path)`。若可修改缓存目录项的本地主体在两次打开之间将临时路径换成符号链接，链接目标会在打开时被截断，随后被缓存字节覆盖。写完后拒绝符号链接只能阻止提交，不能撤销目标文件损坏。

本次仅修复规则缓存文件 I/O 与对应测试，不改变规则优先级、裁剪、配置、DNS、Debug、公开 Rust API、C ABI、Swift API、缓存格式版本 2 或已有错误码，也不进行版本发布。

## 实现与所有权

- `Temporary::create` 用 `read + write + create_new` 排他创建普通文件，Unix 保持 `0600`；创建成功才构造清理守卫，避免创建失败后误删既有文件或符号链接。
- `Temporary` 持有路径和原始文件句柄，直至提交或失败清理。`cache::write` 只借用该句柄，不再接收路径，不重新打开文件，也不截断文件。
- 写前拒绝非空或非普通文件；预算准入仍在序列化和写入之前。超限拒绝且文件保持零字节，不新增缓冲或预算子池。
- 写入、刷盘、回退到文件开头及固定栈缓冲内容复核使用同一个句柄。路径被换成符号链接或硬链接都不会改变写入目标。
- 准备完成和原子提交前拒绝符号链接及非普通目录项；Unix 进一步核对设备号与 inode，拒绝替换成另一个普通文件。正常更新与旧 YAML 迁移均检查。
- Unix 读取缓存使用 `O_NOFOLLOW | O_NONBLOCK`，在打开时拒绝最终符号链接，并避免被换成 FIFO 后阻塞；打开后仍验证文件类型与大小。
- 失败不发布新规则快照；保留既有原子提交和提交后目录同步的耐久性语义。临时文件清理错误仍通过现有诊断设施报告。

## 信任边界与剩余限制

缓存目录必须是宿主受信任的应用私有目录。排他创建和文件句柄消除了本次“跟随替换后的路径截断外部目标”的写入机制，但不能据此宣称可抵御对整个目录持续拥有写权限的恶意主体。

目录或父目录替换、硬链接别名、校验与 rename 间仍可能发生的恶意目录项替换，以及同身份进程直接篡改文件，属于更大的目录信任边界；本次不把路径复核称为完全原子的防篡改提交。`O_NOFOLLOW` 只约束最终分量，不保护全部父目录。缓存摘要用于检测损坏，不作来源认证。

Unix 的设备号/inode 校验与打开标志使用条件编译；非 Unix 复用原始句柄写入与内容校验，但没有新增等价的原子无跟随打开及文件身份保证。不得将本次 macOS 测试当作 Windows 或 Linux 运行验收。

## 示例与回归

正常调用示例为 `examples/binary_rule_cache.rs`：通过 `Store::open` 和 `Store::update` 生成两版规则，保留旧决策，再关闭、重载并验证新决策；不连接网络，不接触真实用户配置。执行：

```bash
cargo run --locked --example binary_rule_cache
```

`src/routing/store.rs` 中 `cache_path_tests` 的七项确定性回归覆盖：原句柄写入重载、非空文件不截断、创建冲突不误删、创建后替换成符号链接时外部目标不变、普通文件替换拒绝、既有符号链接不误删、更新失败保留快照/旧文件/目标内容并清理临时文件。

其中符号链接替换测试在生产创建与生产写入之间明确更换目录项，不依赖竞争线程碰巧命中窗口。断言预期来自“不损坏链接目标、不发布无效新快照”的要求，而不是复制当前实现。

真实 Swift FFI 在 `Tests/ffi_runtime_rules.swift` 中使用实际 Rust 更新入口，覆盖缓存目标符号链接拒绝、目标与旧文件不变、快照版本不递增及恢复后重新加载。
