# 正式域名协议组合、规则预算与构建验收

作者：可莉唯一的狗。日期：2026-10-15。

本轮一起处理正式“域名 + 传输协议”条件、原 runtime.rs 审查编号 08 与 10。仅交付 dev 源码；不改 App，不合并 main，不创建版本标签，不发布 crates.io 或 XCFramework。下列验证范围不包含真实系统 VPN、Intel、最低 macOS 或移动系统。

## 独立业务契约与实现

正式 Rule 增加可选 `protocol`，允许 `tcp` / `udp`，仅可与 `DOMAIN`、`DOMAIN-SUFFIX` 组合，表示 AND。无该字段保持既有规则语义；错误类型、字段、未知/重复字段均受严格校验，即使来源禁用也不能藏匿非法组合。全域 `transport` direct/proxy 仍非法；全域 QUIC reject 保持有效。UDP 不能冒充 QUIC，`protocol: quic` 明确拒绝。

当前域名阶段依次为：有效正式拦截、DOMAIN+协议、DOMAIN-SUFFIX+协议、普通 DOMAIN、普通 DOMAIN-SUFFIX、DOMAIN-KEYWORD；每种类型内部本地先于远程，随后按来源/规则原始顺序。协议不符的组合不算域名命中，不阻止 DNS 后的 IP 规则。域名命中跳过 IP、数字目标直接查 IP、端口/全域传输仅在普通主条件未命中时参与，均保持原规范。已授权 Debug Overlay 仍最高，可覆盖正式拦截；不得突破授权、TTL 或资源边界。

```yaml
rules:
  # 只针对 api.example.net 的 UDP；有效拦截先于下面的普通域名直连。
  - type: DOMAIN
    value: api.example.net
    protocol: udp
    policy: reject
  - type: DOMAIN
    value: api.example.net
    policy: direct
```

TCP 应直连、UDP 应拒绝；`other.example.net` 不命中该组合，执行已有规则或兜底。Rust 可运行例子：`cargo run --example domain_transport`。构造 Rust Rule 字面量时新增 `protocol: None` 或 `Some(Transport::Tcp/Udp)`；已有内部调用与示例已同步。Swift 在 `RoutingRule` 初始化时传 `protocol: .udp`；这是内核 SDK 的值类型扩展，Swift 不匹配规则。

`src/routing/runtime.rs::Entry::class` 集中定义具名候选槽位；数值仅用于存储。组合和不限定协议的规则不能错误去重；TCP/UDP 分别存候选，查询时先排除另一协议，再判断是否命中域名。普通索引和平铺索引采用同样准入条件。裁决顺序在 selected 中显式列出，与枚举顺序分离；参考实现对组合使用独立条件和来源变量，不调用生产分类/选择函数。

`Tests/runtime_rules.rs` 用独立业务预期验证来源、AND、拦截、协议不符等待 DNS、覆盖裁剪、同域异协议及 YAML/二进制往返；6000 目标随机差分也包含组合，不把差分自洽当作独立语义证明。`src/routing/debug/semantic_tests.rs` 验证调试覆盖组合拦截及撤销后恢复；专用 IPC 的授权边界没有放宽。

## 兼容性与缓存迁移

C ABI 仍为版本 2，追加能力位 27，既有能力位不改义。Swift configure / 结构化来源更新只在使用组合时检查该能力，旧固定二进制没有该能力则明确 unavailable；普通规则不强制要求新能力。SDK 本次源码与已发布二进制分别管理，Package.swift 固定版本及 SHA 不变。

缓存候选记录宽度扩充，`src/routing/cache.rs::VERSION` 从 1 改为 2；规则文档版本仍为 1。版本 1 不能按新宽度误读，也不自动回退 YAML：停止旧 Store、归档生成缓存，从原主配置/订阅重新生成；保留原缓存用于回滚。回滚需要恢复旧程序与旧缓存，不能混读。dev API 可演进，本轮不触及 main 已发布契约。

## 原 08：共享预算与校准

编译、平铺、缓存 I/O、解析输入、后台队列的拥有型输入及实际存活快照现在使用同一 512 MiB 规则准入池；此前平铺和缓存各有独立额度，不能表达总准入。后台输入仍受独立的 128 MiB 子配额约束，但必须同时成功预留共享池；任一失败均归还另一租约。输入按 Rule Vec 和字符串实际容量估算，不把完整编译额度重复当作输入堆大小。文件解析租约通过 PreparedInput 接续到来源消费结束，避免解析返回时提前归还配额。单次平铺仍限制估算不超过 256 MiB。预算使用 checked 算术，拒绝返回既有四位资源错误；不新增或改号。

| 估算项目 | 修改前 | 本轮最终 | 含义 |
| --- | --- | --- | --- |
| 每规则构建基数 | 1024 字节 | 1536 字节 | 哈希容量、Entry、元数据和构建临时对象 |
| 每后缀标签 | 512 字节 | 1024 字节 | 扩充候选后的节点、子表容量及构建余量 |
| 每关键词字符 | 64 字节 | 128 字节 | 普通索引和临时模式构建 |
| 平铺每规则基数 | 512 字节 | 768 字节 | 固定候选记录宽度及序列化区段 |
| 平铺每后缀标签 | 160 字节 | 256 字节 | 扁平节点、边和最终缓冲区共存 |
| 平铺关键词字符 | 384 字节 | 384 字节 | 稀疏节点、边、队列及序列化区段 |

来源引用的恢复估算另乘容量余量 2；大量重复规则按 Vec 实际容量校验，收缩上限与租约真实预留额比较，不能与逻辑元素数重新估算比较而误拒绝。构建租约随 FlatIndex 交接，真正释放临时结构后收缩为字节容量；不能先返还预算再让缓冲无预算驻留。树和 Matcher 实际释放后才收缩文档驻留额度，活动连接只保留既定决策、版本标记及必要资源，不引用整份规则快照；新方案提交后新请求只从当前方案获取快照，已有任务不因更新断开。后台更新回归用 Weak 证实旧规则快照已回收时原 TCP 仍能双向传输。压力示例刻意由诊断调用方保留的旧 Arc，仍必须计算实际文档和字节预算，不能为了数据好看提前归还。只读 `runtime::memory_usage()` 报告当前/峰值准入，不提供重置/改变配额入口；没有按次匹配采样或增加日志。

**已确认的校准缺陷与修复证据：** 候选 768 字节/标签方案，10000 条约 35 标签后缀、三次更新保留旧快照与四线程生成/恢复，time -l 实测峰值 607928320 字节，虽然准入峰值未超过 512 MiB，仍未达本轮 RSS 目标。提高到 1024 后，同场景在后续更新返回 8002，旧缓存/快照保留，引用释放后恢复成功。失败证据保留在 `/private/tmp/fluxa-rules-measurements/candidate/stress-suffix-10000.log`；最终重复数据另存验收附件，不能用失败候选冒充最终值。

**边界：** 512 MiB 是统一估算准入，不是整个进程 RSS 或分配器硬限制。宿主自行分配输入、线程栈、其它模块、分配器留存都可能在池外；有限测量不能证明全部合法输入、平台或长期并发永远低于该值。高复杂度形态可在十万条数量上限前受控拒绝。本轮验收覆盖固定矩阵，长期压力仍单列 TODO。

## 原 10：测量方法与目标

当前平铺缓存，没有恢复 SQLite。修改前基线为已提交 e090b367d96fd6979ed383b007f1bae122c326cc 源码的独立优化程序；两方案采用同一混合基准数据与本机条件，每档三轮交替、独立进程。测量时没有并行编译或 FFI 测试。编译列是普通内存索引编译；两次原子更新包含编译/平铺、元数据编码、完整复核、文件与目录同步、快照切换及失败判断。RSS 为 macOS time -l 峰值，单位字节；不是纯索引大小。

目标在最终结果前写入 `Tools/check_rules_acceptance.py`：1000/10000/50000/100000 条两次更新每轮分别不超过 300/600/1800/3000 ms；中位数不超过同条件基线两倍；固定矩阵 RSS 不超过 512 MiB。该目标是本机工程验收标准，不是跨平台 SLA。查询用更新生成的各自兼容缓存，在完全独立的新进程只恢复后测首、尾和未命中各 20000 次及四线程 400000 次；纳秒 p99 受计时分辨率限制，不推出真实网络速度。

压力示例 `examples/rules_acceptance.rs` 包含八来源、精确/组合/高标签后缀、关键词、IPv4/IPv6、重复规则、三次更新保留旧 Arc，以及四线程同时恢复和生成。成功或资源准入拒绝均需检查；非资源错误导致失败。十万重复规则必须成功合并，不能把任意资源拒绝当作通过。压力结束必须池占用归零，释放旧引用后仍可恢复完整缓存，不以逻辑关闭提前归还实际存活内存。

最终数据与实际命令在下节登记；附件包含二进制 SHA-256、主机与编译器信息、所有三轮样本。历史 SQLite 对比保持原文，不与本轮比较混算。

## L1–L4 与实际结果

L1：fmt --check、check --all-targets、clippy --all-targets -D warnings、Swift 严格格式检查均通过。没有运行 SwiftLint / SwiftFormat，不能把 xcrun swift-format 当成这两项。

L2：全量回归、输入租约交接、双完整 YAML 严格规则编译、缓存未知版本/损坏/篡改、随机差分、真实协议数据面、FFI 与错误契约检查通过。引用类压力场景结束后实际预算归零，资源失败后可恢复。

L3：独立依据用户的 AND、拦截、本地同类型优先、Debug、错误不默认放行和会话契约审查。最小复现包括：远程组合后缀须优先本地普通精确域名；UDP 组合不命中 TCP 时不能阻止 IP/DNS；TCP 实际传输、UDP 组合拦截既不发包也不查 DNS；旧快照弱引用失效时旧 TCP 继续读写、新请求按新拒绝规则执行。原语义不作无关修改，主动关闭/Debug 授权撤销和正式配置更新分别处理。

L4：本节表格全部由本轮真实原始样本汇总；[机器可读原始样本与二进制指纹](RulesAcceptanceMeasurements.json)包含三轮数据和目标程序 SHA-256。没有用历史 SQLite 表、另一版本测试数量或预算高水位代替本轮 RSS。

### 缓存结构与零拷贝范围

所有整数为小端。文件头：8 字节 FLXARULE；4 字节版本（2）；文档/索引长度各 4 字节；4 字节保留零；32 字节 SHA-256；然后连续文档 JSON 和平铺索引，拒绝尾随。文件最大 128 MiB、文档最大 32 MiB；偏移/长度 checked 校验、UTF-8、候选类别与规则序号、哈希探测、树/失败边/前缀结构均经验证。索引区保持十个区段（精确域名、后缀节点/边、IPv4、IPv6、端口、关键词节点/边、传输候选、字符串池），候选为具名槽位，编号不是优先级。

文件读入 Vec 仍有系统复制；平铺索引解析/查询借用不可变字节，不重建执行树，不使用 mmap/unsafe。文档仍反序列化，返回出口仍按值复制。SHA-256 检测损坏，不是来源认证；加载报告仍为 StructuralOnly，不能据此证明原始删除理由。
