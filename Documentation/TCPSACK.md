# TCP SACK 选择确认

作者：可莉唯一的狗。适用 dev 自研 TCP/TUN 数据包路径，不代表系统 VPN 或正式二进制已发布。

## 协商、接收与选择重传

依据 [RFC 2018](https://www.rfc-editor.org/rfc/rfc2018.html)，从 SYN 的 SACK-Permitted（Kind 4、长度 2）
取得协商信息，SYN-ACK 对应回复。未协商的连接不发送 SACK，也不根据外来 SACK 改变发送记录。
SACK（Kind 5）只接受非 SYN 的 ACK，区间数 1–4，每块两个 32 位网络序边界；长度、重复选项、
空或反向区间明确拒绝。区间使用 TCP 模序号比较，支持 32 位回绕。

接收端复用原固定接收环和存在位图，最近到达的乱序块先报告，再重复最近块，不足四块时从位图补齐。
相邻数据合并为连续区间，已经累计确认或越过已知 FIN 的正文不列入 SACK。
位图按 64 位字查找，不为每个碎片分配节点；最多四个历史锚点和四个输出区间。

发送端复用最多 64 条发送记录，每条增加选择确认和本轮已重传标记：

- 只接受已发送且未累计确认区间内的提示，超出已发送右边界或已累计确认左边界的块忽略；
- 只有完全被某个 SACK 块覆盖的记录才标为已选择确认；部分覆盖仍保留并允许保守重传；
- 更高序号至少三条记录或三倍 MSS 字节已经选择确认时，将低序号缺口判为可选择重传；
- 三次重复 ACK 保留首缺口快速重传入口；同一恢复轮不无限重复发送同一缺口；
- 按有界 pipe 估算与拥塞窗口选择后续缺口，恢复结束以进入恢复时的发送右边界累计确认为准；
- SACK 永远不推进累计 ACK，不提前归还正文空间。对端可以撤回 SACK；RTO 清除全部提示和恢复标记，
  重新发送最早未确认记录，重传次数和超时上限继续生效。

此实现是保守的按发送记录选择恢复，不宣称完整实现 RFC 6675 的每字节 scoreboard、部分块拆包或 rescue retransmission。
未知/局部覆盖可能多发已有字节或等待超时，但不能释放未确认正文、跳过有效拦截或改变出站。

SACK 协商连接为四块选项保留最多 36 字节 MTU 空间，再确定有效发送 MSS；即使双向乱序使纯数据包也带 SACK，
新发及重传包都不超过 MTU。未协商连接保持原 MSS、窗口和累计确认行为。窗口扩大仍是独立未交付改动。

## 独立示例

| 输入 | 应有结果 |
| --- | --- |
| 累计期望 101，先收到 601–1100 | ACK=101，SACK=[601,1101) |
| 随后收到 101–600 | 累计 ACK=1101，原 SACK 块消失 |
| 发出十个 100 字节段，仅第 1、4 段丢失，其余已选择确认 | 只选择重传两个缺口；正文保持到累计确认 |
| 对端 SACK 覆盖尚未发送的数据 | 忽略该提示，不释放正文、不扩大预算 |
| 已 SACK 后对端撤回，触发 RTO | 清除提示，重新发送最早未累计确认的数据 |
| 非协商连接收到 SACK | 不用于选择恢复，原累计确认与 RTO 继续工作 |

## 资源、示例与验收

没有新增配置字段、C ABI 命令或公开错误代码。每流固定双 32 KiB 环、4 KiB 位图、最多 64 条发送记录，
新增字段和四锚点在原 256 KiB 租约内；全局 TCP 预算仍 8 MiB、最多 32 条流，默认会话上限仍 16。
选择恢复使用固定 64 项栈数组及线性扫描，无按输入增长的 scoreboard，不创建逐包任务。
关闭与取消继续由内核 authority 撤销、后台任务回收及缓冲 RAII 负责，不依赖前端释放旧引用。
