# F-01：DNS 解析器退休与活动资源清理

作者：可莉唯一的狗。

## 问题与独立业务依据

网络配置替换原先仅切换 Arc，外部保留旧解析器/快照时，旧实例仍可发起查询并占用全局活动解析器名额。监听任务还持有 Resolver，因此 Drop 不能充当资源关闭的业务入口。依据 AGENTS/会话生命周期与资源所有权隔离原则.md，活动权限与对象引用必须分离；依据已确认的更新语义，已准入事务和已建立连接不能仅因配置更新被中断。

最小路径：配置解析器 A，保留旧快照，再提交解析器 B；旧 A 应拒绝新操作，但已经准入的查询/建连可完成，随后内核释放 A 的驱动、监听与活动配额。重复超过 16 次且保留所有旧快照，不能仅因旧引用存在而耗尽活动名额。真正尚在排空的实例仍计入限制。

## 修复边界

- src/dns/mod.rs：独立查询准入与驱动权限；ResolverOperation 按身份绑定，允许已登记事务完成后续解析与提交；退休后台清理，显式 close 仍立即撤销。Drop 补齐监听服务停止兜底。
- src/dns/wire.rs：报文入口先检查准入，畸形报文不能绕过退休状态返回伪成功。
- src/outbound/configuration.rs：全部校验后，在配置锁内退休旧实例再发布；同实例更新不退休，失败不改变旧权限。连接提交必须携带同实例的有效令牌。
- src/outbound.rs、src/outbound/resolution.rs、src/outbound/execution.rs：令牌贯穿共用建连事务及后续 DNS 查询，不只覆盖第一条 DNS 请求。
- examples/dns_retirement.rs：真实回环示例，查询屏障后清除 DNS，原建连成功，旧引用新查询失败。

## 兼容性与后果

未新增配置字段、公开错误码、C ABI 或 Swift 接口。旧解析器在退休后新操作返回既有 InvalidState（9001）；不是规则 REJECT，不触发 DIRECT 回退。同步 configure 返回表示新快照已提交及旧准入停止，不表示已排空；资源释放由内核运行时托管。内部令牌不公开给前端。

已建立连接不持有该令牌，不随 DNS 退休取消。外部旧对象实际保留的配置、缓存及映射内存继续计入原预算；只在真实监听/驱动完成清理后归还活动解析器名额。详细操作契约见 DNS.md 的“解析器配置替换与退休（F-01）”。

## 独立语义核验与执行证据

验证以独立契约为预期：旧新准入隔离；已登记查询成功；退休后同一事务后续查询成功、其他解析器不能借用令牌；在 DNS 中途替换后原连接仍完成提交；24 次替换保留全部旧快照后服务端口可重绑；同实例或失败提交不撤销当前解析器；显式关闭仍取消查询。不能仅以两套实现一致作为依据。

真实命令、版本、dirty 状态及逐用例结果见 tests/test_dns_mod.md 与 tests/test_outbound_dns.md；该说明不替代同名测试报告。静态检查、回归与示例的本轮结果在交付时记录。系统 VPN、真实远程上游长稳压力、最低部署系统及其他平台不在本轮回环验收范围。
