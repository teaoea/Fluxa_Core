## 资源和查询边界

切换布局不增加规则上限，不扩大表容量，不增加查询分配，不取消 64 次探测限制。排序复用精确表，字符串池清空并复用容量，避免残留一份重复域名；排序后只读字节池。普通精确表仍有界探测，碰撞表查询为二分；加载时一次识别严格有序有效行和连续空尾，不在每次查询重新校验。后缀子边的原探测准入未在本次改造，不宣称所有碰撞场景均已修复。

现有 ByteBudget/ByteLease、构建准入和只读快照所有权保留；新增校验循环不构建全量副本或引入 unsafe。压力上界的全部平台实测不在本轮已证范围。

## 缓存格式与迁移

内部二进制缓存版本由 2 升到 3，记录宽度及目录字段不变，但 v3 允许碰撞后的有序精确表。格式版本独立于 Cargo SemVer、YAML 和错误协议。旧版本明确返回现有 Unsupported 错误，不静默接受为空规则，不覆盖旧文件、不自动放行。旧缓存需保留备份并使用原始规则来源在新目录显式重建，验证完成后由既有受控配置提交切换；不要在活动内核中手工删除缓存。回滚时旧二进制使用原 v2 备份，不用 v3 缓存喂旧读者。main、已发布标签及 App 依赖不变，本轮不发布二进制或 crate。

## L1–L4 核验

L1：类型和边界检查覆盖移位 /0、IPv4 高位、/32、/128；短路避免在最长前缀继续计算分支移位。源代码未扩大公开 API 或增加依赖。实际静态命令、完整测试结果以本轮日志及报告为准。

L2：原 15 项保留，新增四项单元回归及一个独立集成用例；完整发现和结果由 Tools/test_reports.py 保存，不以编译成功代替测试。开发中新增父子案例曾选择到叶节点，夹具断言失败；修正为最短前缀父节点后验证无候选中间子树，原预期未降低，历史日志保留。

L3：合法配置必须能在预算内构建；缓存仅长度、编号或摘要合法不能证明规则关系真实；拒绝非法缓存不转成 DIRECT/Continue。策略预期来自固定规则及上述格式不变量，不以实现互相一致循环证明。这里只验证明确列出的索引契约，不宣称整个缓存、所有协议或所有输入均已审计完。

L4：原六项失败在 Git 历史可核对；本轮原始证据目录为 /private/tmp/fluxa-flat-six-first-evidence、second-evidence、third-evidence、fourth-evidence，最终全量证据为 /private/tmp/fluxa-flat-six-final-evidence。报告保留实际源码提交与 dirty 状态；Git 提交后不伪改已执行报告的提交号。远程 CI、真实系统 VPN 与其他平台须分别验证。

## 开发过程中的回归记录

首轮全量回归原六项和当时新增四项均通过，但两个既有缓存测试将数字 3 作为“未知版本”，与本次已登记的 v3 冲突，因此失败。已把输入统一改为固定未分配的 u32::MAX；仍要求加载失败且不回退旧 YAML，未删除或放松断言。首轮失败日志保存在最终证据目录 attempt-1 与 Git 报告历史机制中。
