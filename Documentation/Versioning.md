# 版本号约定

版本号采用 `v主版本.功能版本.修复版本`，初始版本为 `v0.0.0`。

| 变更 | 递增规则 | 示例 |
| --- | --- | --- |
| 新增功能 | 功能版本加一，修复版本归零 | `v0.0.0` → `v0.1.0`；`v0.1.3` → `v0.2.0` |
| 功能版本进位 | 功能版本到 9 后，下一次新增功能使主版本加一，后两位归零 | `v0.9.0` → `v1.0.0`；`v1.9.2` → `v2.0.0` |
| 仅修复 bug | 修复版本加一，前两位保持不变 | `v0.0.0` → `v0.0.1`；`v0.1.0` → `v0.1.1` |
| 同时新增功能与修复 bug | 按新增功能递增 | `v0.1.2` → `v0.2.0` |

修复版本按整数递增，例如 `v0.1.9` → `v0.1.10`，不因 bug 修复进入新的功能版本。

Git 标签与对外版本展示使用 `v` 前缀，例如 `v0.1.0`；Cargo.toml 的 `version`、App 数值版本使用 `0.1.0`，不包含 `v`。新增功能与 bug 修复按一次发布的实际内容确定版本；单纯文档、格式或构建流程调整不自动递增功能版本。

本文件只规定后续版本递增方式，不自动修改当前版本，不重写已经发布的版本或标签。发布与合入 main 仍遵循各仓库的验证及用户授权要求。
