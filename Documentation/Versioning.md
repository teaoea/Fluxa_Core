# 内核版本说明

唯一权威规范为 [《API全生命周期管理》第四章](../AGENTS/API全生命周期管理.md#4-语义化版本与契约版本)。本文件提供示例，不维护另一套版本号约定。旧“功能版本到 9 后进位主版本”规则已移除。

| 变更性质 | SemVer 处理 | 示例及前提 |
| --- | --- | --- |
| 向后兼容的缺陷修复、内部优化 | PATCH 递增 | `2.4.1` → `2.4.2`，须确认公开行为仍兼容 |
| 向后兼容的新公开能力 | MINOR 递增，PATCH 归零 | `2.9.3` → `2.10.0`，MINOR 不限制到 9 |
| 破坏已发布公开契约 | 获明确授权后递增 MAJOR，MINOR/PATCH 归零 | `2.10.2` → `3.0.0`，版本升级不能代替授权及迁移审查 |
| main 中尚未正式发布的开发 API 改造 | 不保证历史 API 兼容；不能直接据此决定正式发布版本 | 与上一 main 正式发布契约核对后，按实际变化确定获准发布版本 |

Git 标签使用 `v` 前缀，例如 `v2.10.0`；Cargo 与 Swift 包版本为 `2.10.0`。不重写已有版本、标签和历史发布记录，不复用已发布版本号。本次规范替换不自动修改 Cargo、Release.version 或依赖版本。

main 已发布的 `0.y.z` API 仍受项目明确授权要求约束；不能借 0.x 绕过不兼容变更审批。内核版本、配置格式、公开错误协议及 GeoIP 等外部数据版本分别维护。

所有分支和通道永久禁止发布 crates.io，Cargo 保持 publish = false；源码提交不构成二进制上传授权。发布来源、兼容性、废弃窗口及独立审查的完整要求以权威规范为准。

## 源码分支与二进制通道

内核源码只有 `main`，功能开发、验证和提交均在 main 完成，不存在 dev 源码分支。
`2.8.0-dev` 中的 `-dev` 与 dev 二进制通道只表示开发预发布的稳定性等级，不表示源码分支，也不构成上传或正式发布授权。
Nodus-Core 源码已开源，后续二进制在同一仓库分发；当前上传入口仍关闭。Fluxa App 的分支及许可另行遵守其约定。
