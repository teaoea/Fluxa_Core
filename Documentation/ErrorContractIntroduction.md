# 错误代码查询表

作者：可莉唯一的狗。

本文是内核公开错误协议的技术契约。权威定义为 `src/error.rs` 的 `define_codes!`，生成 `ErrorCode`、固定整数值、参数 Schema 与下表；`error-codes.json` 是同一契约的机器可读快照，不是另一套独立定义。每个变体有中文说明性注释。

## 协议、用途及兼容性

代码是显式固定的 u16 整数，供机器识别，不依赖枚举排列、自然语言、调用方身份或显示方式。内部 `Error` 保留既有 17 个类别，新增经确认的 ProtocolViolation，并保留 `Result<T>`；`Error::code()` 穷尽映射到公开代码，`public_info()` 提供结构化对象。额外两个 ABI 类别表达真实边界失败。

结构化对象为 `{"code":1006,"params":{}}`。code 与 params 必填，未知代码、未知字段、任何参数键均拒绝。`ErrorInfo::from_json` 在解析前限制为 512 字节。当前没有获准公开的动态参数，不返回域名、文件路径、配置原文、Token、凭据、私钥、对象地址或完整底层错误链；不虚构 field、rule_index 或 trace_id。

`fluxa_engine_command_v2` 在原有 `success:false` 状态之外返回 `error_info`，不格式化自然语言文本；原 v1 的 `error` 文本保留。成功响应不包含 error_info。后台规则 Job 和 MITM Capture 同样增加可选 error_info，原文本兼容保留。原 `fluxa_engine_command` 仍省略所有新增错误字段，保持 v1 JSON；新查询符号与 v2 共用同一权威错误定义和执行流程。代码和文本分离，匹配不分配或比较字符串；客户端不能根据 error 文本判断类型。

C ABI v1 的旧返回值不变。新增 `fluxa_engine_last_error_code()` 直接返回 u16，零表示当前线程没有错误，查询只读取线程本地值，不加锁、不分配或序列化；JSON 查询仅供需要结构化对象时使用。`fluxa_engine_last_error_copy` 是新增的只读查询符号：返回当前调用线程最后一个同步 ABI 操作的错误 JSON 所需长度；没有错误返回零；空目标或容量不足不写入；不分配响应句柄、不清除错误。必须在同一线程、后续业务或缓冲区 ABI 操作之前读取，查询不能跨线程关联。成功业务或缓冲区调用清除旧失败；版本、能力和错误查询本身不覆盖。TUN 的 11 表示队列暂时为空，是状态而非错误。无效指针的实际可读/可写性仍由 C 调用方负责，不能声称内核能够验证任意地址。

## 参数 Schema

| 字段 | 类型 | 必填 | 含义 | 安全限制 |
| --- | --- | --- | --- | --- |
| code | 已登记 u16 整数（JSON 中为数值） | 是 | 固定的业务失败类别 | 不拼接、不包含动态参数、未知值拒绝 |
| params | 空对象 | 是 | 当前版本没有允许公开的上下文键 | 任意新增键均拒绝，不接受嵌套对象或自由文本 |

所有代码使用该空参数 Schema。新增参数须先在权威类型和契约中定义类型、长度、范围及安全限制，更新查询表、机器快照和兼容性基线，并验证失败路径。

## 复杂语义与边界

- 策略主动 REJECT 与执行故障分离：纯 `Router::evaluate` 可成功返回 Reject 决策；出站执行拒绝时沿用 `Error::Rejected`，公开为 1017。远端连接拒绝属于 1007，不能按规则拒绝处理。
- 1001 与 1012 是既有粗粒度类别，不能据此推断具体字段、生命周期或版本冲突。当前实现没有依据输入字符串区分这些子原因，不虚构精确代码。配置验证与原子提交规则保持不变；不把非法文档部分接受。
- Debug Overlay 仅通过 Rust 本地 API 操作，没有 YAML Deserialize 或持久化入口。当前内核不提供认证/授权服务；宿主须先完成认证与授权。不能登记一个并未实际执行检查的 DEBUG_UNAUTHORIZED。错误代码不授予权限。
- 资源错误不会替代预算：响应名额、ByteBudget、队列和计数器检查保持原先顺序。可选 DNS 缓存预算不足仍允许已成功获得的解析结果返回，但必须保留有界诊断；这不是绕过连接/规则预算。
- DNS 负响应按现有 DNS 协议处理；解析失败不得转成默认 DIRECT。1004 包含启用 DNSSEC 时验证查询失败，不声称每次都是签名不合法。
- 内部锁中毒不可恢复为业务成功。诊断环自身的锁只保护固定诊断记录，恢复它不恢复任何业务锁。固定 64 条环只保存代码、业务位置标识、I/O kind 和可选 OS 数字；覆盖数量可见，不保存文本/配置/正文，不持有快照。
- `Error::from(io::Error)` 在最多 16 层受控链内按类型保留包裹的原内核错误，操作系统 TimedOut 分类为网络超时，循环或超深链受控归为原 I/O 类别，并记录底层 I/O 分类。现有 map_err 丢失详细上游原因的路径仍须单独审查；诊断不能声称恢复此前已丢失的错误链。
- 1019 表示响应编码失败，不承诺业务操作没有发生，不能据此自动重试。REJECT、ERROR、队列空、已关闭状态与成功结果不得混用。

旧命令接口在指针、长度及响应资源检查后先验证引擎句柄，再解析命令 JSON。无效句柄与非法 JSON 同时出现时保持句柄失败；有效句柄的非法 JSON 返回 1001。不能为统一错误表示改变既有校验顺序。专项测试覆盖上述输入组合及有效命令的不支持结果。

## 分类、稳定性与维护

下表分别记录实际 Rust 模块及协议分类。当前分类为 INPUT、DNS、RESOURCE、IO、NETWORK、LIFECYCLE、TLS、STATE、CAPABILITY、INTERNAL、SCRIPT、POLICY、ABI、PROTOCOL；没有实现的 AUTH 或 IPC 服务不予虚构。

DNS 查询统计锁中毒返回 1014；不冒充 1002。TUN 响应发布失败保留具体错误分类，同时保留旧 ABI 合并状态。HTTPS/MITM 外层真实 timeout 使用 1008；后台工作任务 JoinError 使用 1014，连接或文件 I/O 保持 1007。上述分类修正保持失败及拒绝行为；可能使旧诊断文本更准确，文本从来不是稳定错误标识。

这是首次语义化整数协议；原来公开的是 Error 类别、诊断文本和 ABI 数值。整数协议从 1001 开始，避免和旧 ABI v1 状态 0–11 混淆；编号只是身份，不是优先级。原 Error 变体、旧文本和 ABI v1 数值不重命名。以后已公开代码不得静默改名、改义或复用；废弃项需保留并标记。`Tests/fixtures/error-contract-v1.json` 冻结首版契约，测试要求已发布项不变。新增代码只能追加并登记，不得通过更新基线掩盖不兼容变更。

运行 `cargo run --example error_contract -- --check` 和 `cargo test --test error_contract`。生成方法为 `--write`；生成后必须独立核实源码、触发条件及处理后果。CI 同时执行一致性和兼容性测试。新增代码但未更新查询表会失败；表格数量相同、自动生成和差分一致均不能证明业务语义正确。审查证据见 `ErrorSystemReview.md`。

## 完整代码契约

ProtocolViolation 经用户确认新增：XUDP 会话、标志及目标绑定失败使用 1020；保持报文拒绝及连接失败行为。旧 TUN 数值状态 9 兼容表示拒绝，新整数代码区分 1017（策略）与 1020（协议约束）。Rust 对 Error 作穷尽匹配的调用方需增加 ProtocolViolation 分支；旧 17 个变体不重命名。

## 历史 ABI 数值状态兼容表

以下不是新 ErrorCode 的编号；定义集中在 `src/error.rs::LegacyAbiStatus`。旧整数协议保留，新增接口查询实际固定 ErrorCode，不能根据旧合并状态猜测具体原因。

| 旧状态 | 含义 | 新协议对应或处理 |
| --- | --- | --- |
| 0 | 成功 | 无错误为 0，0 不登记为 ErrorCode |
| 1 | 无效句柄 | 1018；锁异常使用实际 1014 |
| 2 | 能力不支持 | 1013 |
| 3 | 内部失败 | 1014 |
| 4 | 输入不合法 | 1001 |
| 5 | 配额不足 | 1006；若实际是内部发布失败则查询实际代码 |
| 6 | 状态不允许 | 1012 |
| 7 | 取消 | 1009 |
| 8 | 合并处理失败 | 保留具体 IO、DNS、TLS、脚本类别，不转成策略成功 |
| 9 | 拒绝 | 1017 策略拒绝；1020 协议约束违反 |
| 10 | 合并超时 | 1002 DNS；1008 网络 |
| 11 | 队列空 | 状态，不是错误，不生成 ErrorInfo |

## TLS 包裹错误传播修复

v2.3.1 修正现有 TLS 适配只保留取消、把其他内核错误统一改报为 TLS 的缺陷。已明确的预算、内部状态、取消、协议、能力及状态错误保持原代码；系统内存不足与超时也保留资源／超时分类。只有通用 I/O 在 TLS 阶段归类为 1010。编号、格式、失败结果和规则策略不变。可运行例程为 `cargo test --lib error::tls_mapping_tests`，输入示例 `io::Error::other(Error::ResourceLimit)` 仍返回 1006。该修复不引入新的权限入口，正式核心没有身份验证服务。
