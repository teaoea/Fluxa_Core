# TUN 出站 IP 分片

作者：可莉唯一的狗。

这里的出站指 Rust 向 TUN 宿主交付的 UDP 返回报文，不是把外部 IP 包当路由器转发。
原始请求照常通过 DNS/Fake-IP、规则及直连/代理出站；分片不重做路由决策，也不绕过拦截。
TCP 继续通过 MSS 分段，其报文不需要由本功能额外分片。

## 行为与可运行入口

完整返回 IP 报文小于等于配置 MTU 时，仍交付原有单包。超过 MTU 时：

- IPv4：为本端新生成的报文分配统一 ID，清除本端编码器的 DF，设置片偏移与 MF，逐片计算 IPv4 首部校验和。
- IPv6：本端作为源添加 Fragment Header，所有分片使用相同的 32 位 ID、下一首部 UDP 及正确偏移。
- 两者非末片正文按八字节对齐，UDP 校验和在完整数据报上计算并保持不变。
- 不修改外部 DF 报文；不是任意 IP 转发器，也未实现 ICMP/PMTU。
- Rust API、C ABI 和 Swift 接收接口仍每次交付一个 IP 包。生产 Swift 不复制分片或重组业务。

示例：MTU 1280，UDP 正文 8001 字节。IPv4 产生七片：前六片各 1276 字节，末片 493 字节；
IPv6 同样七片：前六片各 1280 字节，末片 665 字节。宿主必须将每次返回作为独立 IP 包写入 TUN。

```sh
python3 Tools/test_reports.py --run --suite test_tun_fragment --suite test_tun_udp
```

真实 Linux 重组测试仅可在受控网络命名空间中执行：

```sh
cargo build --locked --example tun_tcp_kernel
sudo unshare --net python3 tests/test_tun_fragment_kernel.py "$PWD/target/debug/examples/tun_tcp_kernel"
```

## 资源与生命周期

完整报文仍最多 9000 字节；MTU 保持 1280–9000，不增加 YAML 字段，不放大现有完整包上限。
超过完整包上限明确报资源错误，不能截断。公共单包 `encode_udp` 保持超 MTU 拒绝的契约。
UDP 网络读取采用完整报文上限，不以 MTU 截断 UDP 数据报。

每组最多八片；队列的每个槽现在保存一个完整数据报，宿主读取时依次取出其分片，再取下一数据报。
先构造全部分片，成功后一次入队；分配失败通过 RAII 释放整组，不向队列发布半组。
队列等待取消与后台任务取消均释放实际持有的包；明确关闭还清空已经部分读取的分片组。
宿主已经取走的包属于宿主所有，不因关闭撤回；网络丢片仍可能导致对端重组超时。

包正文继续计入全局 4 MiB 预算。构造期间完整原包与分片同时存在，正文峰值小于 19 KiB/数据报；
队列 1–64 个槽、最多八个 UDP 会话、64 个全局 UDP 流保持原上限。
每槽元数据最多八个 Packet 的有界 VecDeque；另每会话一个最多七片的待读队列、每流最多一组等待发送。
所有这些正文共享 4 MiB 准入，不能把队列槽位变化解释为无界内存；预算不包含进程 RSS 和系统 socket 缓冲。

分片 ID 按地址族在进程中全局递增，关闭或新建会话不重置。IPv4 的 65536 个 ID 耗尽后，
距最后一次分配不足 120 秒时明确拒绝，超过静默期才允许重用；IPv6 的 32 位空间同样处理。
无每数据报定时器、无按目的地址增长的 ID 表。失败消耗过的 ID 不回退。
该保守策略可能在极高分片速率下拒绝请求；不宣称跨进程/重启后的 ID 唯一，宿主不能把多个独立内核的相同 TUN 地址空间混用。

## 独立语义检查及验收边界

L1：检查切片、整数偏移、最多八片、ID 无截断回绕、无 unsafe；实际编译/Clippy 结果另见证据。
L2：测试独立重建传输正文、逐片偏移及校验和，不仅用生产重组器回读；保留现有超完整包上限拒绝断言。
L3：分片只改变返回包表示，规则/出站身份不变；预算中途失败不部分发布；并发关闭清空 pending 和 channel。
L4：真实 Swift FFI 独立向量、Linux 系统 IP 重组分别记录。测试数量、失败和版本见同名报告，不预写通过结论。

本阶段未修改公开错误代码、配置字段或正式二进制依赖。macOS Network Extension 系统接管、最低系统、Intel、
真实用户代理节点及长期高负载仍需单独验收；本功能不代表系统 VPN 已就绪，不授权 main 合并或 crates.io 发布。

开发验证中，Linux 已完成两族字节重组，但首次整体失败：接口自动产生的 IPv6 控制包被送入尚不支持 ICMP 的内核。
夹具现在只转交受测 UDP；仍严格核对数据路径错误为空，不将控制包的 Unsupported 冒充数据路径成功。原始失败证据保留。
