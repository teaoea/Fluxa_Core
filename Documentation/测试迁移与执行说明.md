# 测试迁移与执行说明

本次迁移以《测试文件与报告统一管理原则》全文为约束，测试源码和同名报告统一放在根目录小写 `tests/`。工具映射 `Tools/test-suites.json` 登记真实源码、执行机制、单元模块或集成 Cargo 目标；夹具单独登记，不计独立测试覆盖。

## 实际执行入口

```sh
python3 Tools/test_reports.py --check-layout
python3 Tools/test_reports.py --run --evidence-dir /tmp/nodus-test-evidence
python3 Tools/test_reports.py --check-reports
python3 Tools/test_reports.py --run --suite test_budget --evidence-dir /tmp/nodus-test-budget
python3 Tools/test_reports.py --external test_test_reporting -- python3 tests/test_test_reporting.py
# Swift FFI 已迁往 Fluxa，入口见 Fluxa/Documentation/Swift适配层迁移.md
```

示例路径不代表已经运行；实际结果由每个 `tests/test_*.md` 与对应机器证据记录。

## 注册、隔离和归属

- Cargo 配置 `autotests = false`，集成目标全部显式登记；外置单元套件由真实生产模块使用 `#[cfg(test)] #[path]` 接入。
- 私有模块不扩大可见性。原有同名公开接口用例按用户明确选择并入单元套件，保留原断言；报告按实际执行机制记录为单元测试。
- 单元测试按文件分别在独立测试进程中串行执行，避免原本独立目标合并后共享静态资源配额而互相干扰。进程内测试的断言和生产资源上限不变。
- 先读取 Cargo 真实构建工件，再执行实际 `--list`；每个完整用例名通过显式单元模块/集成目标映射到文件。检查发现但未归属或重复归属的用例会失败，不靠总数猜测归属。
- 测试夹具集中在 `test_fixture_*.rs`，无独立用例，不以零测试通过冒充覆盖；Swift 测试与执行器已迁至 Fluxa，内核不再登记 SwiftPM。

## 真实状态与历史

- 构建失败记录 COMPILE ERROR，断言未执行，不伪造失败用例数量。
- 超时与中断保留子进程真实状态；执行器另以非零状态退出。
- 原有忽略的外部对端测试不偷偷启用，也不计通过；有忽略项的套件标 PARTIAL。
- 未执行的 Swift XCTest、外部协议或夹具独立目标保持 NOT RUN。普通签名 IPC 用例无专用环境时只证明签名拒绝分支，不代表加固签名和实际 Swift 授权分支通过；该分支由 Fluxa 的 `Packages/FluxaKernelBridge/Tools/check_debug_ipc.py` 独立验证。
- 每次报告包含实际提交、dirty、平台、工具链、命令、退出状态和源码/断言/构建指纹。指纹不包括报告自身；源码、配置、执行器、规范或夹具变化会使旧报告失效。
- 本地证据保存在执行时指定的目录；CI 使用带 Run ID 和 Attempt 的上传工件。相同证据目录内每次外部执行保留独立 attempt JSON/日志和更新前报告，编译与运行不会相互覆盖。
- 报告生成器不能自动完成 L3。迁移审查核对断言保留、模块路径和测试发现，未重新验证的全部业务语义明确标为未验证。

## CI 与发布边界

新增验证工作流仅有只读仓库权限，执行静态检查、真实 Rust、报告工具失败保全，始终上传报告/证据；不发布 crate 或二进制。既有发布工作流同步新测试路径及报告入口，移除“仅修改发布工作流就自动发布”的触发路径；Release.version 与手动发布入口保留。本次任务不触发发布、不合并 main。

旧测试文档中的命令和路径如用于历史证据保留原样；当前入口以本文件、Cargo 与套件映射为准。迁移尚不等于每个 src 文件都有充分测试，更不能将原断言全部通过当作全部业务语义已证明。

## 本轮迁移审查范围

迁移输入包括已有 299 个 Rust 用例声明，名称及数量核对无缺失、无新增；此数量不是业务正确性证明。对应核对保存在 `Tools/test-migration-audit.json`。单元套件 38 个、独立 Rust 集成目标 13 个；公共接口用例合并为单元机制的决定来自用户明确回复，未删除断言。

迁移运行观察到 `test_routing_flat` 的 scenario_01、02、03、04、05、08 六项断言失败，原样保留为 FAIL；分别涉及哈希同槽准入、IPv4/IPv6 零前缀规范化、子节点所属前缀/分支及节点候选归属。失败本身不代替独立业务缺陷定性，本轮不擅自修改生产策略或测试预期。该状态应阻止质量门禁通过和正式发布，不能以其余套件通过掩盖。

L3 本轮独立核对范围是迁移未扩大生产 API、原测试断言保留、测试归属与运行机制准确、资源隔离不靠放宽配额、失败/忽略/未执行没有改成成功。原有全部协议和规则业务语义并未因此重新全面审查；相关测试报告明确保留该边界。

## Swift 适配分离

Swift 封装与 24 个 Swift 测试文件已迁至 Fluxa 仓库 `Packages/FluxaKernelBridge/`，包括报告和执行工具。内核保留 51 个 Rust 套件、1 个 Python 工具套件及 5 个支持夹具，共 57 个映射。跨仓库联调在 Fluxa 显式指定受测内核路径；不属于生产构建依赖。
