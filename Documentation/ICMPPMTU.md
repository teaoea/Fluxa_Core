# ICMP 错误与路径 MTU

作者：可莉唯一的狗。适用 dev 自研 TCP/UDP 数据包会话；不表示系统 VPN 已接管或新二进制已发布。

## 两段路径

TUN 客户端至 Rust 虚拟端点这一段，由自研 TCP/IP 处理；Rust 至真实目标或代理服务器这一段，
使用系统 Socket，仍由操作系统处理该段 PMTU。不能将代理服务器路径的 MTU 直接用于客户端数据包，
也不因 ICMP 创建连接、解析 Fake-IP、重选规则、切换 DIRECT 或修改系统路由。

当前支持 ICMPv4 Destination Unreachable、Time Exceeded、Fragmentation Needed，以及 ICMPv6
Destination Unreachable、Time Exceeded、Packet Too Big 的受限输入。
非 MTU 错误按软提示处理，不凭单个未认证 ICMP 中止活动 TCP/UDP；原连接仍按真实 I/O、重试与期限结束。
Echo/Ping、Redirect、Source Quench、Parameter Problem 及任意原始 ICMP 出站不在本次范围，明确拒绝，
不回显假冒远端可达。没有可匹配流的引用不能建立新流。

## 输入与关联

1. 先执行既有有界 IP 重组和 IPv6 扩展头规范化，再验证 ICMP 长度、类型/代码、校验和、地址族及外层目的地址。
2. ICMPv6 校验和包含伪首部。引用允许仅含 IP 头及前八字节；不把截短引用送入完整 TCP/UDP 包解析器。
3. 引用只接受本内核实际生成的基本 IP 头或首个 IPv6 Fragment 头；非首片、嵌套错误、零端口、组播和无效引用拒绝。
4. TCP 必须匹配现有反向四元组、代次、已真实发送且尚未累计确认的序号和对应输出长度。
   不在途、未发送、已确认、错序号及错长度均不能更新 PMTU。
5. UDP 每流只记四个近期引用，保存固定头部字段，不保留正文。要求匹配地址、端口、长度、传输头及 IP 标识，期限 30 秒。
   非分片 IPv4 标识、IPv6 Flow Label 区分流生命周期；IPv4 标识与分片共用不重复序列，IPv6 Flow Label 使用独立 20 位序列。
   序列耗尽须经历 120 秒静默期再使用，失败返回资源错误，关闭不会重置全局序列。
6. 这些检查是受限关联检查，不是密码学认证；能观察/伪造正确活动报文的攻击者仍可能注入 ICMP。
   控制输入不能绕过宿主句柄、会话身份或代次。未知引用与校验失败明确拒绝。

TCP 复用现有有界输入队列，不逐包创建任务；工作任务验证失败通过现有错误队列报告，保留原流。
UDP/虚拟 DNS 的路径记录属于原会话，关闭主动清空；过期或旧会话引用不能恢复活动资源。

## MTU 与重传

- PMTU 反馈只降低估计，不因更大数值增加。IPv4 最小 68；旧式 MTU=0 按 RFC 1191 的下一平台值降低。
- IPv6 最小按 1280 处理。当前没有主动探测增大；TCP 路径估计随流关闭释放。
- 接口配置范围仍为 1280–9000，内部有效路径 MTU 与接口配置校验分开，不能借反馈放宽配置。
- TCP 重新计算发送 MSS、裁剪 SACK 选项数量；在途大记录按较小片段重传、按累计确认归还字节。
  有效累计进度允许继续处理尾部，保留 Karn 重传歧义与有界重试；无进度不能无限占用资源。
- UDP 的后续返回数据报使用新 MTU 分片；已经取出的旧数据报不重放，未确认可靠性交给相应上层协议。
  完整报文仍最多 9000 字节、最多八片；极小 MTU 下超过八片明确返回资源错误，不交付半组。
- 虚拟 DNS 返回复用同一分片路径；每会话路径数量受 maximum_flows 约束。近期引用过期不代表允许立即抬高已降低的 MTU；
  DNS 降低后的记录至少保留十分钟，之后才可清理。满额明确拒绝，不忽略限制。

每个 UDP 路径对象编译期限制在 1 KiB 内；普通流全局最多 64，DNS 每会话最多 32、会话最多 8，
这部分固定路径对象上界 320 KiB，不包括 HashMap 容器开销；引用数组固定四项，没有逐包持久分配。
TCP 仍受既有 8 MiB 流预算，包缓冲仍受共用 4 MiB 预算；没有提高接口流数量或正文上限。

## 独立输入示例

| 输入 | 预期 |
| --- | --- |
| 活动 IPv4 TCP 真实返回大包，引用正确，MTU=296 | 后续及在途重传包不超过 296，累计正文与半关闭保持完整 |
| 活动 IPv6 TCP，MTU=1200 | 有效路径按 1280 处理 |
| 引用正确但声称更大 MTU | 不增加估计 |
| 引用 IPv4 长度 1428、MTU=0 | 使用下一平台值 1006 |
| 新 UDP 流四元组及正文与旧流相同，收到旧引用 | 标识不一致，不能调整新流 |
| 已关闭会话收到控制包 | 状态错误，不恢复连接 |
| UDP MTU=576、1400 字节正文 | 三片返回，独立重组后正文完整 |
| IPv4 极小 MTU 导致超过八片 | 资源错误，不截断、不返回部分片组 |

源码联调示例：

```sh
python3 Tools/test_reports.py --run --suite test_tun_icmp --suite test_tun_tcp_state --suite test_tun_udp
```

没有新增配置字段、错误码、C ABI 命令或生产本地依赖。复用无效输入 1001、不支持 1021、状态错误 9001、
资源上限 8001 及既有队列/预算错误；语义以统一错误表为准。

## 独立验证与实际边界

L1 核对截短切片、固定数组、整数、MTU 下界、SACK 选项空间及无 unsafe。
L2 使用独立 ICMP 字节向量、已知数值、小窗口/乱序/重传/关闭回归，不以生产输出反推预期。
L3 核对外层目的/引用方向、实际在途证据、旧 UDP 生命周期、原规则及 DNS 所有者、无新连接和无 DIRECT 回退。
L4 由同名测试报告记录执行状态、源码指纹、真实失败、原始日志及未测项目；专项通过不能替代全量结果。

开发中曾观察到片段接口下限测试失败：将内部路径 MTU 直接混入原接口配置下限。现保留原校验及断言，
仅在受限路径编码入口支持较小 IPv4 MTU；相关失败记录保留在原始证据中。

最终 Linux 复跑也暴露既有任务登记测试的同步假设：AbortHandle 完成可见不保证 JoinSet 的完成
通知已可消费。测试保留每轮登记不超过两项的断言，并在两秒内实际调用回收、验证仅剩活动任务后
才开始下一轮；未放大生产配额、未移除资源断言。原失败与重跑结果分别保留。

最低系统、Intel、macOS Network Extension 真机接管、长期高负载、无 ICMP 反馈的黑洞探测/PLPMTUD、
原始 ICMP 代理仍未测或未实现。正式发布须走授权 main 流程，dev 不发布 crates.io。
按照用户新顺序，本阶段完成后优先 App API 接入，其他 TUN 高级扩展延后。

整合最新主配置后，真实 Swift HTTPS FFI 曾在 GCD 工作线程发生栈保护 SIGBUS。
请求入口现将大型 HTTP future 的构造推迟到有界 Rust 工作线程，并固定到堆上；共用取消守卫
保持同步退出时终止子任务。新增 256 KiB 宿主栈回归，另以真实 Swift TLS 请求验收；失败证据保留。

最新主线的 global 使用 final/fallback，而非仅凭出站名称自动选择代理；Swift 互通夹具现显式传递
proxy fallback。端口与后缀的用例按已登记优先级分开验证，不改写内核路由语义。真实 TCP 半关闭
测试也严格验证可能合法重传的已收范围及字节一致性，不把重复段拼入应用正文，仍验证完整正文与 FIN。
嵌套 Tokio 调用现受控返回 9001，取代过去依赖 block_on panic 的零句柄；无脱离任务断言保留。
