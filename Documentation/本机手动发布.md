# 内核本机手动发布

2026-10-19 起不依赖 GitHub Actions 发布。测试、构建和验证在受控本机完成；源码仍只推送私有 Fluxa_Core/dev，公开 libfluxa-core 只接收二进制和有限来源清单。

1. 完成格式、全目标 Clippy、Rust 测试、错误契约及真实 Swift FFI，保存原始退出状态、失败历史及未测边界。
2. 提交本次文件并推送 dev，在干净副本重跑检查。生成本机验证摘要，字段为 source_commit、fingerprint、checks 和 unverified。checks 必须逐项包含 format、clippy、rust_tests、error_contract、swift_ffi，均使用 status: PASS 与 exit_code: 0。未测项不能计通过。
3. 设置 FLUXA_DEV_SOURCE 为完整提交、FLUXA_DEV_REPOSITORY 为 teaoea/Fluxa_Core、FLUXA_DEV_VERIFICATION 为摘要文件，再运行 bash Tools/dev-release.sh --prepare <全新附件目录>。目录保留便于手动上传；不需要上传令牌。
4. 仅上传 provenance.json、FluxaEngine.xcframework.zip、fluxa-test-fixture-macos-arm64.zip。公开清单记录 manual-local: 后跟本机摘要 SHA-256，不上传摘要原文或原始日志。
5. 在 libfluxa-core 选择 Draft a new release，标签为 v<版本>.<完整私有源码提交>。标签必须指向分发仓库自身的来源清单提交，不把私有源码推入公开仓库。
6. 保存草稿后重新下载三个附件，核对清单、SHA-256、源码提交、架构和包内容。通过后启用 Pre-release 并公开，不更新稳定 latest，不覆盖已发布版本。

可选本机命令 Tools/publish-core-binaries.py 支持现成的有限分发授权，执行相同草稿和下载核验。没有凭据则使用正常登录网页；不为发布创建或扩大访问权限。

当前只交付 macOS ARM64，最低部署目标 14.0；其他平台、最低系统运行、真实签名 App/Network Extension 和系统 VPN 的未验收边界必须保留。源代码、测试、构建脚本、用户配置和日志不得进入公开附件。永久禁止 crates.io。
