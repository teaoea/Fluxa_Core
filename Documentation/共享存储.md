# Core 共享存储与默认配置

本轮仅修改内核，契约以用户 2026-10-19 更新的 example_config.yaml 为依据；不包含 App 接入、安装或 App 打包；内核成品按 dev 不稳定版本单独发布。

## 系统存储边界

组标识固定为 group.app.fluxa.ios。macOS 先从当前进程 Security Task 读取真实 application-groups entitlement，再通过 NSFileManager 的 containerURLForSecurityApplicationGroupIdentifier: 取得容器；其他 Apple 平台直接由系统沙盒容器 API 验证授权，不调用 macOS 专用验权接口。不读取 HOME、不接受远程配置中的写入路径、不创建假共享容器。缺失权限为既有 9001；不支持平台为 1021；文件 I/O 使用既有 6001。内部路径不进入回复或生成配置。运行规则二进制存于同一容器内部独立的隐藏缓存目录，避免规则提供者整目录交换误删二进制；不存入旧 Application Support。

| 数据 | 相对目录 |
| --- | --- |
| 主配置 | config/config.yaml，或用户明确保存的 YAML 文件名 |
| 规则提供者与 GeoIP 数据库 | rule/<name>.yaml、rule/geoip.mmdb |
| 文件日志根目录 | log/ |
| 插件资源根目录 | plugin/ |

日志的等级/日期/小时布局继续遵守主示例；本轮只提供统一根目录，未实现非 silent 文件日志或插件下载器。已有未实现能力继续明确拒绝，不伪造落盘成功。规则/GeoIP 保留原整目录事务、校验、预算、租约及缓存格式，不迁入未经验证的旧 HOME 数据。

## Rust 与 C ABI

- storage::initialize()：幂等检查，配置目录没有任何 .yaml/.yml 时创建 config.yaml；返回本次是否创建。扩展宿主拒绝初始化，不创建目录或文件。
- storage::read_configuration(filename)：读取并严格校验主配置，返回持有预算、释放清零的 ConfigurationText；扩展允许读取。不创建锁或目录。
- storage::save_configuration(filename, yaml)：显式保存，先校验完整配置、再原子替换；与运行配置提交分离。扩展宿主拒绝写入。
- C ABI 继续 ABI 2，能力位 30 代表此组受控存储命令。storage_initialize 返回 default_configuration_created；configuration_save 只接受 filename 与 yaml；configuration_load 只接受 filename，返回带内存预算并清零释放的 configuration_yaml 正文。读取只对本进程宿主开放，不产生网络监听，也不自动记录正文。runtime_rules_open 也改为无目录参数，由 Core 固定共享容器内部缓存目录；旧 directory 参数严格拒绝，不静默忽略。未知字段、外部绝对路径和自报角色不能取得写权限。

示例命令：

```json
{"operation":"storage_initialize"}
{"operation":"configuration_save","filename":"config.yaml","yaml":"rules: ['final,reject']"}
```

读写的宿主身份来自系统 NSBundle 的 NSExtension 信息或 .appex 包类型，不能由命令参数自报。该检查约束 Core API；不能将单元测试结果描述为操作系统对共享组内任意进程的文件 ACL 隔离。真实签名 App/Network Extension 的容器联调尚未验证。

## 默认配置与并发

Core 内置简体中文和英语注释；中文设备使用中文标点，其他支持范围外语言明确回退英语。每个输出字段均有说明，包含项目和问题反馈链接，提示反馈前去除凭据、私钥和敏感内容。不写实际保存路径。

默认配置包含当前已支持的全部主配置字段，但不包含 proxies、proxy-groups；提供者为空，DNS/TUN/MITM/GeoIP/监听关闭，日志 silent。无节点时唯一兜底 final,reject，不自动使用 DIRECT、不发起示例地址下载。用户完整示例中的示范节点和活动示范提供者不复制进首次启动配置。

文件操作绑定目录描述符，使用 openat/NOFOLLOW 拒绝目录及最终文件符号链接；配置最多 4 MiB。读取有并发总预算，目录扫描有条目上限。初始化与显式保存共用同进程串行准入和跨进程独占文件锁；默认文件先写 0600 临时文件，同步后排他 linkat 发布，不覆盖并发创建的目标。显式保存使用同目录原子 rename，语法或业务校验失败保留旧文件；扩展不持有写入入口。

## macOS 团队前缀共享组修复（2.7.1-dev）

macOS 从 Security 当前进程动态代码身份取得真实签名团队，校验后使用 `<TeamID>.app.fluxa.shared`。组名必须同时存在于进程的 application-groups entitlement；不读取配置、环境变量或宿主传入的路径。签名无效、无团队或缺少共享组时仍拒绝存储操作，保持原错误传播。

例如团队 `DVXRRLRJ78` 对应 `DVXRRLRJ78.app.fluxa.shared`。此 macOS 格式不需要 App Group 描述文件；iOS 保留 `group.app.fluxa.ios`，不能套用 macOS 规则。实际目录仍由 Foundation 返回，不拼接 Group Containers 路径。

切换不会自动读取、复制或删除旧容器。新容器是独立存储；只在其 config 目录没有任何 YAML 时按原规则生成默认配置。已有配置须由用户通过明确的文件导入授权带入；不能把新容器默认配置误报为旧配置已迁移。无效签名与真实容器读写须分别验证，编译通过不代表系统授权通过。
